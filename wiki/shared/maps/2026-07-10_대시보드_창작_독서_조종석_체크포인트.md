# 2026-07-10 대시보드 창작·독서 조종석 체크포인트

## 한 줄 요약

> vault 대시보드는 이제 단순 전체 지도가 아니라, 상단에서 **창작 사이클의 현재 비행 위치**와 **독서모임의 현재 해석 좌표**를 각각 보여주는 이중 조종석으로 확장되었다.

## 오늘 확정한 문제의식

기존 대시보드는 전체 글감 지도와 독서모임 연결을 보여주는 데는 유효했지만, 두 가지 한계가 있었다.

1. 창작 쪽은 “지금 이 후보가 A/B/C 어디에 있는가”를 즉시 답하지 못했다.
2. 독서모임 쪽은 책들을 “몇 개의 글감을 낳았는가”로만 보이게 해서, 책카드·close-reading·비교 강의·질문망의 독립적 가치가 가려졌다.

따라서 대시보드의 목적을 다음처럼 재정의했다.

| 탭 | 새 역할 | 중심 질문 |
|---|---|---|
| 창작 | 집필 조종석 | 지금 어느 희곡 후보가 B/C 어디까지 왔는가? |
| 독서모임 | 해석 조종석 | 어떤 책/질문/비교 강의 축이 살아 있고, 다음 모임에서 무엇을 말할 수 있는가? |

## 1. 창작 cockpit 구현 상태

설계 문서:

- `dashboard/COCKPIT_REDESIGN_PLAN.md`

구현 파일:

- `dashboard/cockpit.json`
- `dashboard/index.html`
- `dashboard/app.js`
- `dashboard/style.css`
- `dashboard/data.js`
- `tools/generate_data.py`
- `tools/test_generate_data.py`

현재 cockpit 초점:

```text
COCKPIT_ACTIVE B→C
COCKPIT_PRIMARY 환대는 기능 자리가 아닙니다
COCKPIT_PHASE B2 구조맵 작성 · B4 검증 통과 · C1 진입 대기
COCKPIT_LINK wiki/writing/draft-candidates/환대는_기능_자리가_아닙니다_단막후보_맵
COCKPIT_SECONDARY 보통 인간 연수에 참석했습니다 — C1 톤 확인 장면 있음 · 정식 B2 구조맵 필요
```

해석:

- [[wiki/writing/draft-candidates/환대는_기능_자리가_아닙니다_단막후보_맵|환대는 기능 자리가 아닙니다]]는 정식 C 조립 전, **B2 구조맵+B4 검증 통과 후 C1 진입 대기** 상태다.
- [[wiki/writing/drafts/보통_인간_연수에_참석했습니다_첫장면|보통 인간 연수에 참석했습니다 — 첫 장면]]은 **C1 톤 확인 장면은 있으나 정식 B2 구조맵이 아직 없는 톤 스파이크**로 표시한다.
- 공식 상태값은 계속 `설계/대기/조립/개작/무대` 다섯 개만 사용하고, `ready-for-c1`, `tone-spike` 같은 값은 UI 파생 상태로만 쓴다.

## 2. 독서모임 reading cockpit 구현 상태

설계 문서:

- `dashboard/BOOKCLUB_READING_COCKPIT_PLAN.md`

구현 파일:

- `dashboard/reading_cockpit.json`
- `dashboard/index.html`
- `dashboard/app.js`
- `dashboard/style.css`
- `dashboard/data.js`
- `tools/generate_data.py`
- `tools/test_generate_data.py`

현재 reading cockpit 초점:

```text
READING_FOCUS 편의점인간
READING_AXIS `보통 인간`은 타고나는 것인가, 모두가 서로를 보며 흉내 내는 가공의 생물인가?
READING_QUESTION 정상성/견본 축을 독서모임에서 어떻게 말할까?
READING_METRICS {'closeReadings': 10, 'questionLinks': 5, 'lectureLinks': 5, 'writingLinks': 30, 'derivedNotes': 26}
READING_TOP [('편의점인간', 104), ('서사의위기', 78), ('작별하지않는다', 69), ('마션', 62), ('모든것이산산이부서지다', 59)]
```

해석:

- 독서모임 탭은 더 이상 `글감 26`만 전면에 내세우지 않는다.
- [[wiki/bookclub/books/편의점인간/00_책카드|편의점 인간]]은 현재 **정상성/견본/기능 자리**의 해석 허브로 표시된다.
- `읽기 / 질문 / 비교 / 창작 / 글감 파생`을 분리해 보여준다.
- 기존 제목 `가장 많은 글감을 낳은 책들`은 `오래 남은 책들`로 바뀌었고, 정렬 기준은 `derivedNotes`가 아니라 `readingScore`다.

## 3. 현재 대시보드 데이터 생성 상태

검증 명령:

```bash
python tools/test_generate_data.py
python tools/generate_data.py
node -c dashboard/app.js
node -c dashboard/data.js
```

따라서 성능 병목은 데이터 파싱보다, 초기 로드 시 모든 탭과 서랍을 한꺼번에 DOM 렌더링하는 구조일 가능성이 높다.

## 4. 다음 개선 과제

### 1. 초기 로드 최적화

다음에 손볼 최우선 개선:

```text
탭 lazy render
```

- 최초에는 창작 탭만 렌더한다.
- 독서모임 탭은 사용자가 탭을 누를 때 처음 렌더한다.
- 한 번 렌더한 뒤에는 재사용한다.

추가 최적화 후보:

- 잠자는 계열 table은 details를 열 때 렌더.
- 책 서가는 처음 20권만 보여주고 나머지는 details로 접기.

### 2. 상태 source 정밀화

현재 cockpit은 `dashboard/cockpit.json`, `dashboard/reading_cockpit.json`으로 세션 초점을 고정한다. 이후 장기적으로는 다음을 검토할 수 있다.

- `log.md` 최근 항목 기반 자동 초점 추정.
- 계열 지도 비고 열에서 `B4 통과`, `톤 확인` 같은 문구를 더 정교하게 읽기.
- 독서모임 reading cockpit에서 강의 후보/완성 강의 상태를 분리.

### 3. 편의점 인간 다음 작업

창작:

1. [[wiki/writing/draft-candidates/환대는_기능_자리가_아닙니다_단막후보_맵|환대는 기능 자리가 아닙니다]]를 계열 지도에서 `대기`로 정식 전이할지 결정.
2. 승인 시 C1 첫 장면 조립.
3. [[wiki/writing/drafts/보통_인간_연수에_참석했습니다_첫장면|보통 인간 연수]]는 톤을 살릴 경우 B2 구조맵 작성.

독서모임:

1. `편의점 인간 × 코뿔소 × 사람, 장소, 환대` 10분 해설 압축.
2. 정상성/견본 축을 독서모임 질문망으로 별도 정리할지 판단.

## 5. 커밋/푸시 상태

- 커밋/푸시는 하지 않았다.
- 현재 작업 트리에는 오늘 대시보드 변경 외에도 이전 세션의 운영 규칙·책카드·질문노트·편의점 인간 계열 파일들이 함께 남아 있다.
- 다음에 커밋하려면 먼저 변경 묶음을 분리하는 것이 안전하다.

## 오늘의 핵심 문장

> 창작 탭은 “무대까지의 현재 비행”을 보여주고, 독서모임 탭은 “책들이 만든 해석 좌표”를 보여준다. 책은 글감의 원료만이 아니라, 질문과 강의와 기억의 중심이다.
