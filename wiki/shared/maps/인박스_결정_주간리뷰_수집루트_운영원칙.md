# 인박스·결정·주간리뷰·수집루트 운영원칙

## 한 문장

이 vault는 자료를 많이 저장하는 곳이 아니라, 캡처한 조각을 질문형 노트·창작 장치·결정 기록·주간 압축으로 승격시키는 장치다.

> Inbox는 받는 곳이다. Weekly Review는 고르는 곳이다. Decision note는 닫는 곳이다. Question/map/note는 살아남는 곳이다.

## 1. Inbox

- 위치: `wiki/_inbox/`
- 세부 위치:
  - `wiki/_inbox/quick-captures/`
  - `wiki/_inbox/web-clips/`
  - `wiki/_inbox/raw-ideas/`
  - `wiki/_inbox/to-triage/`
- 빠른 캡처, 웹 클립, 아직 분류 전인 글감, 회의/대화 파편을 임시로 둔다.
- Inbox 노트는 오래 머물지 않는다. 정리할 때는 질문형 노트, 창작 노트, 연결 지도, 책카드 보강, 결정 노트, archive/폐기 중 하나로 판정한다.
- 캡처 시점에는 완성도를 요구하지 않는다. 다만 출처와 왜 붙잡았는지는 남긴다.

## 2. Decision note

- 공통 결정: `wiki/shared/decisions/`
- 희곡/집필 결정: `wiki/writing/decisions/`
- 책모임/강독 결정: `wiki/bookclub/decisions/`
- `log.md`의 짧은 결정 기록만으로 나중에 이유가 흐려질 때 별도 노트로 승격한다.
- 특히 운반체 경합, 민감 소재 가상화, 집필 큐 재정렬, 투고/분량/협업 규칙, 서명칸 계보처럼 반복 논쟁이 될 수 있는 판단을 남긴다.
- 결정 노트는 `무엇을 정했는가`보다 `무엇을 버렸고 언제 다시 열 수 있는가`를 함께 보존한다.
- 이 구조 자체의 도입 이유는 [[wiki/shared/decisions/인박스_결정노트_주간리뷰_도입|인박스·결정노트·주간리뷰 도입 결정]]에 남긴다.

## 3. Weekly Review

- 위치: `wiki/shared/reviews/weekly/`
- `log.md`가 사건의 append-only 기록이라면, 주간 리뷰는 작업 판단의 압축본이다.
- 매주 모든 것을 정리하려 하지 말고, 남은 질문·새 연결·승격할 글감·결정·다음 초점만 적는다.
- 주간 리뷰는 다음 Hermes 작업의 출발점으로 쓸 수 있어야 한다.

## 4. 승격 규칙

모든 임시 기록은 다음 중 하나로 승격되거나 폐기되어야 한다.

- Inbox item → note / question / map / decision / delete
- `log.md` 항목 → weekly-review / decision-note / 작업 노트 / 유지
- weekly-review 항목 → 다음 주 초점 / decision-note / 질문 노트 / 글감 노트
- decision-note → 관련 map 또는 question에 연결

승격 기준:

- 한 번만 등장한 생각은 Inbox나 log에 남겨도 된다.
- 두 번 이상 반복되면 question 또는 note로 승격한다.
- 작업 방향을 바꾸는 판단이면 decision-note로 승격한다.
- 여러 책/희곡/글감을 잇기 시작하면 map으로 승격한다.

## 5. Web Clipper 수집 루트

- Obsidian Web Clipper로 들어온 자료는 곧바로 `wiki/bookclub/`이나 `wiki/writing/`에 넣지 않는다.
- 먼저 `wiki/_inbox/web-clips/`에 두고, Hermes가 출처·핵심 문장·질문 후보·희곡 장치 후보를 선별한 뒤 승격한다.
- 웹 원문 전체를 저장하는 것보다, 나중에 해석을 재검토할 수 있는 출처 URL과 핵심 문장, 그리고 내 작업과의 접점을 남기는 것을 우선한다.

## 6. 태그는 상태, 링크는 의미

- 태그는 처리 대기·검토 같은 상태나 처리 목적을 표시할 때만 최소 사용한다.
- 의미 연결은 태그가 아니라 질문형 노트 wikilink와 frontmatter 배열로 만든다.
- `중요`, `아이디어`, `자료`처럼 거의 모든 것에 붙을 수 있는 태그는 쓰지 않는다.
- 링크는 개수를 채우기 위해 붙이지 않는다. 연결이 해석을 바꾸거나 다음 작업 경로를 열 때만 붙인다.
