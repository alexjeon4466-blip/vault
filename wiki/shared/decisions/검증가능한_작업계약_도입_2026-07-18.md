# 검증 가능한 작업 계약 도입 — Ouroboros에서 필요한 부분만 차용

## 결정

> Q00의 Ouroboros를 현재 Hermes 환경에 설치하거나 상시 실행하지 않는다. 대신 `작업 계약 → 단계별 검증 → 수렴·중단`이라는 세 축만 기존 Hermes 작업 방식에 이식한다.

Ouroboros는 자연어 요청을 Seed로 고정하고, 에이전트 실행과 평가를 반복해 수렴시키려는 구현이다. 개념과 구현은 단순한 데모 이상이지만, 현재 환경에는 Hermes의 작업 목록·위임·백그라운드 실행·세션·Kanban·검증 도구가 이미 있다. 전체 프레임워크를 추가하면 기능 중복, 상태 계층 증가, 비용 증가, 권한 우회 위험이 효용보다 커질 가능성이 높다.

## 가져온 것

### 1. Seed-lite — 실행 전 작업 계약

큰 YAML 사양을 만들지 않고 필요한 항목만 비례적으로 사용한다.

```yaml
goal: 관찰 가능한 결과
constraints: 반드시 지킬 조건
non_goals: 이번 작업에서 하지 않을 일
assumptions: 질문하지 않고 채택한 기본값
completion_evidence: 산출물·명령·측정·출처 확인
stop_conditions: 반복·시간·비용·위험·사용자 판단 경계
```

작은 일은 2–5줄로 충분하고, 여러 단계는 작업 목록, 여러 세션에 걸친 일은 프로젝트의 결정 노트·계획·Kanban에 남긴다. 사양 문서 자체를 만드는 일이 본 작업보다 커져서는 안 된다.

### 2. 모호성 게이트 — 결과를 바꾸는 질문만

다음 중 하나에 해당하고 도구나 기존 자료로 답을 찾을 수 없을 때만 질문한다.

1. 답에 따라 산출물이나 실행 경로가 실질적으로 달라진다.
2. 잘못 추정하면 파괴적이거나 되돌리기 어렵거나 외부에 공개된다.
3. 취향·권한·자격 증명·정책처럼 사람의 판단이 필요하다.

그 밖에는 가정을 짧게 밝히고 실행한다. 명세를 완벽하게 보이게 하려고 다중 라운드 인터뷰를 만들지 않는다.

### 3. 단계별 검증

- **1단계 — 기계적 증거:** 테스트, 빌드, 린트, 파일·스키마, 링크, 미디어 probe, 실제 시스템 조회.
- **2단계 — 계약 대조:** 목표·제약·비목표·약속한 산출물을 실제 결과와 비교한다.
- **3단계 — 독립 검토:** 보안·대규모 변경·상충하는 증거·불확실한 설계·품질 우선 요청에만 별도 검토자를 붙인다.

테스트 통과만으로 사용자 요청 전체가 완료되었다고 보지 않고, 에이전트의 성공 보고도 독립 증거로 보지 않는다.

### 4. 수렴·중단 규칙

- 완료는 에이전트의 자신감이 아니라 `completion_evidence`의 충족이다.
- 같은 근본 원인의 실패가 두 번 반복되면 접근법을 바꾸거나 독립 진단을 받는다.
- 테스트 삭제, 기준 완화, 요구사항 누락으로 억지 통과시키지 않는다.
- 인접 문제를 해결한다는 이유로 범위를 자동 확대하지 않는다.
- 파괴적 명령·자격 증명·외부 공개·결제·사람의 미학적 판단 경계에서는 멈추고 증거와 선택지를 제시한다.

### 5. 완료 영수증

큰 작업은 필요할 때 다음 네 항목으로 끝낸다.

```text
생성·변경한 것:
검증한 방법:
남은 불확실성 또는 블로커:
다음 제안:
```

원시 로그를 모두 전달하지 않고 상태 변화, 검증 결과, 사용자 판단이 필요한 문제만 남긴다.

## 영역별 적용

| 영역 | 적용 방식 |
|---|---|
| 코드·자동화 | 작업 계약과 3단계 검증을 모두 적용. 신뢰하지 않는 저장소는 임시 복제본·worktree·sandbox에서 다룬다. |
| Obsidian/wiki | 노트 생성만이 아니라 index·log·링크·frontmatter·검증까지 완료 증거로 본다. |
| 미디어 | 출력 파일 존재에 더해 codec·duration·loudness·chapter/label·샘플 재생을 확인한다. |
| 리서치 | 현재성 있는 1차 출처, 날짜, 링크, 불확실성 표시를 증거로 남긴다. |
| 희곡·창작 | 형식·분량·사실적 연속성 같은 제작 제약에만 경량 적용한다. 의미·미결·미학을 기계적으로 수렴시키지 않는다. 세부 경계는 [[wiki/writing/decisions/우로보로스_개념_이식_2026-07-18\|우로보로스 개념 이식]]을 따른다. |

## 가져오지 않은 것

- Ouroboros 패키지의 상시 설치와 별도 MCP/런타임 계층
- 별도 이벤트 DB와 TUI
- 고정 6단계 오케스트레이션
- 모든 작업의 다중 모델 합의
- `--yolo`, permission bypass, hook 자동 승인
- 사용자 승인과 예산 경계가 없는 재귀적 자기개선 루프
- 작품의 모호성을 결함으로 보고 낮추는 수치형 평가

## Hermes 반영 상태

재사용 절차는 Hermes 스킬 `verifiable-task-contract`로 만들었다. 이 스킬은 새 프레임워크를 호출하지 않고 기존 도구·작업 목록·위임·세션·Kanban과 `verification-before-completion`을 연결한다.

## 재검토 조건

다음 세 종류의 실작업에서 한 번씩 사용한 뒤 과잉 절차인지 확인한다.

1. 코드 또는 자동화 작업
2. Obsidian/wiki 또는 미디어 작업
3. 출처 검증이 필요한 리서치

계약 작성 시간이 실행·검증 시간보다 커지거나, 사소한 일까지 형식화하거나, 질문을 줄인다는 명목으로 위험한 가정을 숨기면 즉시 축소한다. 반대로 반복 누락이나 완료 오판이 줄면 현재 경량 형태를 유지한다.
