# 집필 파이프라인 — 실행 정본

> **이 문서가 작업 순서의 정본이다.** 씨앗에서 잠금까지의 경로를 여기서 정한다. [[wiki/writing/aesthetics/집필_파이프라인|전체 파이프라인]]은 이제 **참조 문서**다 — 각 단계의 근거·상세 판정·드문 예외를 담으며, 평소 작업에서 열 필요가 없다.
>
> **2026-08-17 v3.0 개편.** 실사용 로그를 재보니 단계 어휘(C2 30회·C3 22회·B4 21회·B1.5 13회·C4 13회)는 활발한데, 판본 상태 기계(`workflow_phase`·`canonical_branch`·`lock_only`·`operation` 등)는 **언급 0~1회에 작업 원장 5/5가 전부 기본값**이었다. 한 번도 돌지 않은 기계였으므로 삭제했다. 대신 **실제로 사고를 막은 것**(대상 판본 결박)은 강화했다 — 같은 날 보정 실험에서 워킹트리 파일을 그냥 썼다면 3,685자 자란 개작본을 옛 점수와 비교할 뻔했다.

## 0. 불변 헤더

본문을 읽거나 고치거나 검증하기 전에 적는다.

```yaml
work_id:                  # 미등록 원고면 unregistered
target_revision:          # 정확한 파일 경로
target_checksum:          # SHA-256. 못 만들었으면 not_done, 숨기지 않는다
revision_mode: 신규집필 | 퇴고 | 구조개작
evidence_target:          # 증거를 묶을 정확한 revision
```

- **평가만 요청이면 상태를 만들지 않는다.** `work_id: unregistered`로 두고 대상 경로·체크섬만 적는다.
- **증거는 `evidence_target`의 정확한 revision에만 묶는다.** 판본이 바뀌면 증거도 다시 본다.
- 외부 낭독·C4·판본 비교 전에는 **체크섬을 반드시 만든다.** 이것이 이 헤더에서 가장 값나가는 한 줄이다.
- 작품별 지속 정보(진행 여부, AI 이용 이력, 공모 자격, 검증 증거)는 작업 원장에 둔다 — §10.

## 0.5 모든 희곡 평가의 필수 표시

종합 평가, 퇴고·개작 판정, 피드백 번역, 가상 낭독·실연 결과에는 다음 한 줄을 빠뜨리지 않는다.

`[약·물] 약속=허용|P2|P1|P0|미평가 / 소유=해당 없음|본문|제작|기술|미평가 / 상세=OFF|ON`

아래 등급표는 [[wiki/writing/aesthetics/연극적_약속_물성_판정_카드#1. 모든 희곡 평가의 필수 표시|판정 카드 §1]]의 운영 사본이다. 등급 정의를 여기서 바꾸지 않는다.

| 약속 판정 | 기준 |
|---|---|
| 허용 | 약속 안의 크기·횟수·시간 압축, 대표 구역, 노출형 전환, 안전 대체 |
| P2 | 낮은 등급의 고증·수치 어색함, 특정 제작안에서만 생기는 난도 |
| P1 | 선포한 약속 불일치, 핵심 기호의 가독성 실패, 필수 상태 계보 모순 |
| P0 | 통제되지 않은 중대한 위험 또는 핵심 인과·발견·결말을 보존할 해법 없음 |

- **`허용 / 해당 없음 / OFF`가 정상 종결값이다.** 이 표시는 희곡을 물성 중심 미학으로 강제하지 않는다.
- 자료가 부족해 약속이나 소유를 가를 수 없으면 `미평가 / 미평가`로 남기고 숨기지 않는다.
- 소유는 문제를 **어디서 해결하는가**다. `제작`은 합리적 상연안 선택, `기술`은 안전·큐·리셋 운용, `본문`은 일관된 상연 해법 자체가 없는 서사 물리·약속 결함이다.
- **합리적 해법이 여러 개 있으면 `제작`이며 희곡을 감점하지 않는다.** 텍스트·R0은 해법의 가능성까지만 말할 수 있고, 실제 저항·후열 시야·안전·리셋은 R3·R4 전에는 `미확인`이다.
- 문제가 여러 개면 합치지 않는다: `P1/본문(표면 계보) + P0/기술(젖은 바닥)`.
- 시간 조직이 관련되면 뒤에 `시간=엄격 리얼타임|대표·압축|혼합`을 붙인다(무관하면 `해당 없음`). enum 진실원은 [[wiki/writing/aesthetics/희곡_길이별_설계_원리#1.1 세 가지 시간 계약|길이 원리 §1.1]]의 기록값이다.

`P2` 이상이거나, 사물·공정·시간·시야·안전·리셋이 사건이나 결말을 운반하면 `상세=ON`으로 두고 [[wiki/writing/aesthetics/연극적_약속_물성_판정_카드|판정 카드]]를 연다. 그 밖에는 한 줄로 닫고 멈춘다.

## 1. 어디서 시작할까

| 현재 자료 | 진입 |
|---|---|
| 미선택 씨앗·메모 | 사이클 A — 포착·숙성·사용자 선택 |
| 사용자가 지금 개발하기로 선택한 씨앗 | A→B 이관 패킷 → B 보호 |
| 장면 조각, 형식 미정 | B 탐색 (가장 싼 소시험) |
| 끝까지 연결되지 않은 초고 | C1 |
| 처음 편입하는 완성 초고 | C2 역산 |
| 미잠금 판본의 퇴고 | C3 |
| **잠긴 판본을 다시 쓸 때** | **잠긴 파일을 덮지 않고 새 파일에서 C3** (또는 계약을 바꾸면 B 보호·구조 맵) |
| 잠긴 판본의 제출·증거 확인만 | C4 증거 감사 — 본문 불변 |
| 평가만 | **상태를 만들지 않는다** |

기존 원고를 처음 편입할 때는 **C2 역산이 우선**이다. B 전체를 소급 작성하지 않고, C2가 지목한 병목에 한해서만 해당 단계로 돌아간다.

## 3. B — 쓰기 전 최소 기록

네 가지만 적는다.

1. 지금 붙드는 사람·목소리·이미지·상황
2. 아직 설명하지 못하거나 모르고 싶은 것
3. 다음에 써볼 수행 단위
4. C1 전에 닫아야 할 권리·안전·물리적 불가능

형식 후보는 작업실 규격([[wiki/writing/aesthetics/희곡_길이별_설계_원리|길이 원리]] §4.0 — 단막 = 단일 공간·연속 시간·무대 인원 1~5) 안에서 먼저 만들고, 규격 밖으로 가면 B 보호에서 이탈을 명시 선택하고 이탈 비용을 구조 맵에 적는다.

막히면 가장 싼 소시험을 한다. 형식표보다 2–5쪽 장면이 싸면 먼저 쓴다.

착수 게이트 통과:

- 다음 수행 단위를 쓸 수 있다.
- 잠정적 진행 가설이 있다.
- 관리되지 않은 비가역 가정이 없다.
- 나머지는 C1에서 발견할 항목으로 이름 붙였다.

## 4. C1 — 무감사 집필

사용자가 고른 정지점까지 구조표·점수표·기능감사를 열지 않는다.

- 한 장면
- 한 시퀀스
- 반복 묶음
- 초고 스프린트
- 첫 연결본

정지점에서만 네 줄:

1. 계획과 같았던 것
2. 새로 발견한 것
3. 설계를 반박한 것
4. 더 따라가고 싶은 것

## 5. C2 — 연결 초고 판정

끝까지 읽은 뒤 여섯 가지만 정한다.

1. 현재 작품 동일성 계약
2. 자연 규모
3. 퇴고 / 구조개작
4. 상류 병목 1–3개
5. 아직 검증하지 못한 실연 위험
6. `[약·물]` 한 줄과 상세 카드 가동 여부 (§0.5)

처음 편입한 완성고도 여기서 같은 여섯 항목만 역산한다.

**통과:** 핵심 엔진과 끝까지 읽을 수 있는 경로가 성립함 → 기준 revision과 최소 측정 상태 생성 → C3.

**미통과:** 대상 revision을 증거판으로 보존 → 반증된 층에 따라 C1 또는 B 구조 맵. B 문서는 소급 작성하지 않는다.

최소 측정 상태도 남긴다.

```yaml
observed_manuscript_length:
audience_time_range:  # 실측 범위 + 근거 등급(R1~R4). 점추정 금지 — 길이 원리 §4.1
estimated_speaking_time:
estimated_nonverbal_time:
self_read_R1: done | not_done
observed_engine_layers: []  # 사후 관찰, 개수 목표 아님
```

측정하지 않은 값은 추정치로 발명하지 않고 `not_done`으로 기록한다. 시간 추정·실측은 **범위로** 적는다(길이 원리 §4.1).

엔진 수는 B에서 목표값으로 고정하지 않는다. 여기서는 고정된 revision에서 실제로 작동한 층위만 사후 관찰하며, 많고 적음은 점수도 `lineage_stage` 승격 근거도 아니다.

## 6. C3 — 한 회차

경량 승인 봉투:

```yaml
target_revision:
target_checksum:
output_revision:
purpose:
scope:
protected:
```

한 회차는 기준판, 승인 범위, 수정 묶음, 새 revision, 판정까지다.

- 선택한 엔진이 있는 층부터 고친다.
- 문장 증상보다 원인이 상류라면 상류를 고친다.
- **구조개작이면 부모판을 덮지 않고 새 파일에서 B로 돌아간다.**
- 개작 로그 하나에 병목·수정·되돌림·측정·다음 판단만 붙인다.

평가가 필요하면 [[wiki/writing/aesthetics/희곡_평가_교리|희곡 평가 교리]] §1 용도 라우터로 간다 — 단일 진본 병목 진단은 §2 진단 5모듈(점수 없음이 기본), 판본 비교는 §3 익명 3렌즈, 외부 심사 좌표는 §4 6영역. **어떤 점수도 잠금이나 승격을 자동으로 일으키지 않는다.** 점수와 무관하게 `[약·물]` 한 줄은 표시한다.

## 7. 어떤 증거가 있는가

> 운영 사본이다. 단일 진실원은 [[wiki/writing/aesthetics/집필_파이프라인#C3-3. 낭독·실연 증거|파이프라인 C3-3]]이며 `알 수 있는 것 / 알 수 없는 것`까지 그쪽에 있다.

| 등급 | 증거 |
|---|---|
| H1 | 실제 독립 인간의 묵독·서면 피드백 — 발화·실연 증거 아님 |
| R0 | AI 가상 낭독·다중 시뮬레이션 — 오독 가설, 실제 시간 아님 |
| R1 | 자가 음독·녹음 |
| R2 | 실제 외부 테이블리딩 |
| R3 | 동선·오브제 런 |
| R4 | 기술 런·공개 낭독·공연 |

핵심 물성이 결말을 운반하면 짧은 극도 R3까지 간다.

## 8. C4 — 잠금

텍스트·공모 제출 잠금:

- 전편 R1
- 적용 가능한 실연 연속성 패스
- 남은 특정 오독·구조 질문이 있으면 R0 또는 H1

낭독·공연 준비 잠금:

- 전편 R2
- 핵심 물성이 있으면 R3

공통:

- **P0 없음.** `P0/기술`은 현재 구현의 공연 준비 잠금을 막을 뿐 자동 본문 결함이 아니다 — 안전한 대안이 확인되면 새 구현으로 다시 시험한다. `P0/본문`은 안전하고 반복 가능한 대안이 없고 본문이 그 위험·인과 실패를 강제할 때만 성립한다.
- **실연 연속성 패스 완료.** 각 항목은 `문서상 확인 / 실제 시험 / 미확인 / not-applicable`로 기록하고, 핵심 결말 물성·안전·상연 가능성의 고위험 항목이 `미확인`이면 C4를 막는다. `상세=ON`이면 그 전에 판정 카드를 `관객 판단 → 네 층 → 약속 지도 → 네 시계 → 최종 귀속` 순서로 분해한다. 현실 공정을 전부 재현하지 못한다는 사실만으로 본문 결함을 만들지 않는다.
- **정확한 revision과 증거가 결박됨** — 체크섬 필수
- 작품카드에는 `independent_silent_read_H1 / virtual_reading_R0 / self_read_R1 / external_table_read_R2 / stage_test_R3 / technical_or_public_run_R4`를 각각 기록하고, 하지 않은 시험은 `not_done`
- 출발점과 달라진 이유를 기록함
- 목표 공모가 있으면 최신 요강·AI 자격 확인
- **잠근 파일은 그대로 보존하고 수정은 새 파일에서 한다.** 잠금본 파일명에 버전(vN)을 붙이고, 다음 잠금은 그다음 번호를 쓴다 — 작품카드의 잠금 목록이 유일한 대장이다

## 9. 돌아갈 곳

| 발견 | 이동 |
|---|---|
| 대사·큐·국소 동선 | C3 |
| 진행 가설·관계·물질 경로 실패 | B 구조 맵 |
| 자연 규모·인물 수·시공간·형식 변경 | B 보호 |
| 작품 동일성 계약 변경 | 부모판 보존 → 새 파일에서 B 보호·구조 맵 |
| 편별 독립성과 장막 종속성(F5↔F4) 판정 변경 | 연작 공통 / B 보호. 연작 전체 설계 무효화 |
| 잠긴 판본의 본문 수정 | 잠근 파일 보존 → 새 파일에서 C3 |
| 잠긴 판본의 본문 불변 증거 감사 | C4 증거 감사 |
| 현실과 다르지만 인과·약속이 보존되고 안전한 해법이 있음 | `허용/제작·기술` — **본문 수정·감점 금지** |
| 약속 불일치·필수 기호 미가시 | `P1/소유 층위` — 본문이면 C3 또는 B 구조 맵, 제작·기술이면 R3/R4 |
| 현재 구현의 중대한 안전 위험 | `P0/기술` — 구현 중단 뒤 안전 대안 시험 |
| 안전한 대안이 없고 본문이 위험 물리를 강제 | `P0/본문` — C3 또는 B 구조 맵 또는 구조개작 검토 |

> 문제의 크기가 아니라 어느 가설이 반증됐는지로 돌아갈 층을 정한다.

## 10. 작업 원장 — 작품당 하나

단계마다 다시 쓰지 않는 지속 정보만 둔다. 헤더(§0)는 회차마다 쓰고, 원장은 작품이 사는 동안 이어진다.

```yaml
work_id:
activity: active | paused | archived
current_revision:         # 지금 작업 중인 파일
locked_versions: []       # 잠근 판본 목록 (파일명 + 체크섬 + 날짜)
submission_target:        # 목표 공모가 있을 때만
contest_eligibility:      # 목표가 있으면 필수
  target:
  rule_source:
  checked_at:
  status: eligible | disclosure_required | unclear | ineligible
ai_provenance: []         # append-only. 날짜·모델·작업·영향 revision
validation_evidence: []   # H1·R0–R4 실제 증거
```

- **`ai_provenance`는 지우거나 덮어쓰지 않는다.** 과거 이용을 소급해 "사용자 단독"으로 바꾸지 않는다.
- 목표 공모의 AI 규정이 `unclear`면 그 공모를 목표로 한 추가 AI 개입을 멈춘다.
- 재개할 때는 본문을 읽기 전에 `activity`와 `current_revision`·체크섬을 확인한다.

> **2026-08-17 삭제된 필드.** `workflow_phase` · `canonical_branch` · `working_branch` · `branches` 레지스트리 · `latest_locked_version` · `next_lock_number` · `lock_only`/`lock_and_promote` · `operation` · `depth` · `module_depth` · `delta_review` · `lineage_assessment`. 실사용 로그 언급 0~1회, 작업 원장 5/5가 전부 기본값이었다. **기존 원장 5건은 소급 수정하지 않는다**(append-only 기록) — 새 원장부터 위 양식을 쓴다. 근거와 삭제 경위는 [[wiki/writing/aesthetics/집필_파이프라인|참조 문서]]에 있다.
