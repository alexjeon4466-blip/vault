# 집필 파이프라인 — 사이클 A·B·C

> 글감이 무대에 오르기까지의 세 사이클. 새 발명이 아니라 이미 vault에 있던 실천(폐기_전_확인의 조립, 거울을_옮기는_사람의 개작, 저는의 출품)을 명시적 절차로 승격한 것. 2026-07-05 설계, 사용자 승인.

## 전체 지도

```
사이클 A: 트리아지        사이클 B: 구체화              사이클 C: 집필
(무엇을 쓸까)             (초고 착수 가능하게)           (완성까지)

노트 → 채점 → 계열 →     소집 → 구조 맵 → 물성 →       조립 → 연결본 → 개작 루프 →
처방 → 집필 큐            게이트(8축 재채점)             피드백 → 완성 게이트

[설계]                    [설계 → 대기]                  [대기 → 조립 → 개작 → 무대]
```

대시보드의 "무대까지의 거리" 선반이 이 상태 기계와 1:1 대응한다. 각 사이클 종료 시 `tools\대시보드_갱신.bat`.

- **사이클 A**는 [[wiki/writing/aesthetics/글감_판정_루브릭|루브릭]] 보칙 2에 정의됨 (자율 완주 방식).
- **사이클 B·C는 협업 방식** — 아래 협업 규약 참조.

---

## 사이클 B — 구체화 (유망★ 1편 → 초고 착수 가능)

**입력**: 집필 큐에서 고른 유망★ 노트 1편 (+처방 쌍둥이). **출력**: `대기` 상태의 구조 맵 세트.

### B1. 소집 (여러 노트의 연결이 일어나는 자리)

- 운반체 확정 — 큐/계열 지도의 경합이 남아 있으면 여기서 판정.
- **부품 서랍 소집**: 계열·병합 지도에서 이 계열의 병합 판정 부품 전부 + 교차 계열의 관련 부품을 목록화. 쓸 것과 안 쓸 것을 표로 확정 (안 쓰는 부품은 사유 한 줄 — 서랍은 다음 극을 위해 남는다).
- 처방 재독 + 재해석 4렌즈 방향 확정 (가상화 결정이 있으면 이 시점에 이행).

### B2. 구조 맵 — `draft-candidates/<작품>_단막후보_맵.md`

폐기_전_확인·좋은_직원입니다 형식을 표준으로:
- 장 구성 (5~8장, 각 장의 문제와 출입)
- 무대규칙 (하지 않을 것 포함 — 금지 목록이 미학)
- 인물표 + **정보량 차이표** (누가 무엇을 언제 아는가)
- **오브제 권한 이동표** (수정된_보호자의 명단→출입증→의자→봉투 방식)
- B5 부재축 (무대 밖에서 현재를 바꾸는 것)
- 결말 후보 2~3개 (확정하지 않음 — 조립하며 고른다)

### B3. 물성 3종

- `<작품>_대사_어휘표.md` — 상수 문구(반복될 말), 금칙어(설명어·감정어), 인물별 어휘 결
- `<작품>_물성표.md` — 오브제의 실물 사양(무엇이 실제로 무대에 있고 어떻게 변형되는가)
- 재해석 최종 검증 — 판별 질문 통과 확인 (원작 몰라도 완결 / 아는 관객에게 다른 작품)

### B4. 게이트 — 8축 재채점

구조 맵 기준으로 루브릭 8축 재채점. **전축 ○ → `대기` 승격** (트리아지 지도에 기록). 하나라도 △ → B2로 회귀 (최대 2회, 그래도 안 되면 큐로 반납하고 사유 기록).

## 사이클 C — 집필 (대기 → 무대)

**입력**: `대기` 상태의 구조 맵 세트. **출력**: 출품 가능 상태의 작품 + 작품카드.

### C1. 장면 조립 → 상태 `조립`

- 장별 초안을 **개별 파일**로: `draft-candidates/<작품>_<장면명>_초안.md` (폐기_전_확인 방식 — 장면 단위라 실패해도 국소적)
- 두 장면이 모이면 `<작품>_연결부_퇴고표.md` 시작 (이음매는 장면만큼 중요)
- 조립 순서는 자유 — 첫 장면부터일 필요 없음 (가장 확신 있는 장면부터)

### C2. 연결본 선언 = 초고 성립

- 전 장면 완성 시 `drafts/<작품>_1-N장_연결본.md` 생성 — 이 파일의 존재가 "초고 있음"의 정의.
- 장별 파일도 `drafts/`에 병행 보관 (거울 방식).

### C3. 개작 루프 → 상태 `개작` (반복, 회차 기록)

거울을_옮기는_사람이 확립한 4박자 + 피드백:
1. **기능 감사** — `notes/<작품>_<대상>_기능감사.md` (반복어·상수 문구·오브제가 실제로 일하는가)
2. **현재판 평가** — `notes/<작품>_현재판_평가_<날짜>.md` (루브릭 8축 + 사용자 미학: 균열의 지속, 결말 미해결)
3. **작업 체크리스트 갱신** — `notes/<작품>_작업체크리스트_<날짜>.md` (완료/다음 작업)
4. **본문 수정** (연결본에 직접) + 필요 시 **낭독 리듬 개작** (수정된_보호자 방식 — 소리 내어 읽히는 문장으로)
5. **외부 피드백 회차** (공식 단계): 낭독용 판본 생성 → 모임/지인 낭독 → 피드백을 `script/`에 원본 보관 + 요지를 체크리스트에 반영. 피드백 수용/기각은 사용자 결정 — 기각도 사유와 함께 기록.

### C4. 완성 게이트 — "출품 가능 상태"

세 조건 충족 시 `무대` 승격:
1. 낭독 통과 (외부 피드백 1회 이상 반영 완료)
2. 자체 평가 기준 충족 (현재판 평가에서 잔여 P0 없음)
3. 제출본 서식 완료 (`script/<작품>_v<N>.md/hwp` — 버전 네이밍은 저는 방식: 초고→v3→…→vN)

승격 절차: `plays/<작품>/00_작품카드.md` 생성 (type: play-card, latest_version, submission_target, sources에 전 버전) → 트리아지 지도·계열 지도 상태 갱신 → 대시보드 갱신. **출품 자체는 완성과 별개** — contest/submissions에 별도 기록.

## 협업 규약 (B·C 공통, 2026-07-05 사용자 확정)

- **둘 다 협업**: 구조 맵·어휘표·장면 초안 모두 Claude가 초안 가능. 단 —
- **문장의 최종 소유권은 항상 사용자.** Claude 초안은 제안이며, 사용자가 고친 문장이 그 작품의 문체 기준이 된다. 개작 루프에서 Claude는 감사·평가·체크리스트(진단)를 주도하고, 본문 수정(처방)은 사용자 우선.
- 한 턴의 작업 단위는 장면 1개 또는 도구 문서 1개 — 트리아지처럼 자율 완주하지 않는다. 매 단계 사용자 확인 후 진행.
- 민감 소재 작품은 가상화 확정 문서(쌍둥이의 「가상화 확정」 절)를 B1에서 재확인.

## 폴더 규약 (현행 유지 + 명시화)

| 폴더 | 역할 | 사이클 |
|---|---|---|
| `notes/` | 글감·쌍둥이·감사/평가/체크리스트 | A, C3 |
| `draft-candidates/` | 구조 맵·어휘표·물성표·장면 초안·퇴고표 | B, C1 |
| `drafts/` | 연결본 + 장별 확정본 | C2~C3 |
| `plays/<작품>/` | 작품카드 (완성작의 신분증) | C4 |
| `script/` | 제출본·낭독용·외부 피드백 원본 (버전 아카이브) | C3~C4 |
| `contest/` | 공모 기준·제출 기록·수상 | 출품 (파이프라인 밖) |
