# 집필 파이프라인 — 사이클 A·B·C

> **⚠ 이 문서는 참조 문서다. 작업 순서의 정본은 [[wiki/writing/aesthetics/집필_파이프라인_실행카드|집필 파이프라인 — 실행 정본]]이다.**
>
> 여기에는 각 단계의 **근거·상세 판정·드문 예외**가 있다. 평소 작업에서 열 필요가 없고, 정본과 어긋나 보이면 **정본이 이긴다.**

> **2026-08-17 v3.0 지위 반전.** 실사용 로그에서 단계 어휘(C2 30회·C3 22회·B4 21회)는 활발한데 판본 상태 기계(`workflow_phase`·`canonical_branch`·`lock_only`·`operation` 등)는 언급 0~1회였고 작업 원장 5/5가 전부 기본값이었다 — 한 번도 돌지 않은 기계였다. 정본에서 삭제했고, 이 문서에도 §2 상태 계약을 **삭제 기록**으로 축약했다. 살아남은 것은 실제로 사고를 막은 **판본 결박**(대상 revision + 체크섬)이다.
>
> 여전히 유효한 부분: §0 운영 원칙, §3 작업 깊이의 사고방식, §4~§5의 단계별 상세(B1~B4·C1~C4의 판정 근거), C3-3 증거 등급 진실원.

## 0. 운영 원칙

### 0.1 강행 규약과 선택 렌즈를 분리한다

- **강행 규약**: 상태·판본·가지·권리·안전·출처·공모 규정·AI 이용 이력·잠금 판본의 동일성.
- **선택 렌즈**: 장소, 압력, 대항력, 정보 차이, 권한, 물성, 절차, 범람, 미결 엔딩, 인물 위치.
- 선택 렌즈는 작품이 실제로 호출할 때만 쓴다. 선택하지 않은 렌즈의 빈 표는 만들지 않으며 게이트 통과 조건도 아니다.
- 히라타식 진단 순서는 착수 자격을 판정하는 법이 아니라, 이미 걸리는 장면의 원인을 찾는 도구다.
- 사물·물질을 중심 미학이나 장면 엔진으로 삼는 것은 선택이다. 그러나 선택된 행동·큐·소품이 실제로 수행 가능하고 앞뒤 상태·시야·안전이 이어지는지는 모든 상연 후보의 강행 연속성 조건이다.

### 0.2 문서가 아니라 결정과 증거를 만든다

- 산출물 하나는 적어도 하나의 **결정**, **검증 질문**, **회귀 조건** 가운데 하나를 가져야 한다.
- 본문에 이미 선명한 증거를 표로 다시 옮기기만 하지 않는다.
- 다음 안전한 행동이 분명하면 진단 문서를 더 만들지 않고 쓴다.
- 작품 전체의 작업 깊이와 별개로 물성·윤리·매체·안전 모듈만 더 깊게 검증할 수 있다.

### 0.3 쓰기는 설계의 실행이면서 반증이다

- 초고는 구조 맵을 충실히 복제하는 단계가 아니다. 인물·관계·형식·결말이 설계를 배반해 더 살아날 수 있다.
- 초기 기록은 과거 가설의 증거이지 현재 작품의 의무가 아니다.
- 해석의 모호성과 작업상의 미결정을 구분한다. 전자는 보호할 수 있고, 후자는 위험과 가역성에 따라 관리한다.

### 0.4 자연 규모와 외부 규격을 분리한다

- **이 절이 `자연 규모`의 단일 진실원이다.** 작품의 자연 규모는 핵심 수행·지속·사건, 시간 조직, 관계·정서·지각의 축적으로 판단한다. 값은 C2 측정표의 `짧게 완결 / 유지 / 확장 / 분할`이다. 길이 원리는 시간 조직(F1–F5·시간 계약)과 **규모 이름의 규격**(최소형·단막·장막 — 길이 원리 §4.0)을 소유하며, 자연 규모의 판단은 참조만 한다. 규모 이름은 작업 규격이지 자연 규모 판정이 아니다.
- 공모 매수·시간·형식은 `submission_target`에 따로 기록한다.
- 원고지 매수, 발화 시간, 비언어 시간, 실제 공연 시간은 서로 환산하지 않는다.
- 분량 부족은 사건 추가의 자동 근거가 아니며, 분량 초과는 침묵·노동·반복 삭제의 자동 근거가 아니다.

### 0.5 사용자 결정권

다음 결정은 사용자가 한다.

- 쓸 운반체와 최종 형식 선택
- 작품 동일성 계약의 변경
- 강한 장면·이미지·문장의 폐기
- 현재 기준 가지의 승격
- 출발 기록의 핵심을 버리거나 새 중심 가설로 교체하는 일
- C4 잠금과 외부 제출
- 권리·안전·공모 자격이 불명확할 때 작업 중단·외부 확인·재설계·목표 변경·제출 철회 가운데 무엇을 택할지

AI 협업자는 선택지를 만들고, 읽고, 시험하고, 진단하고, 승인된 범위 안에서 가역적으로 수정할 수 있다.

### 0.6 운영 프로토콜과의 용어·관할 계약

이 문서와 별도 운영 프로토콜은 같은 작품을 보더라도 서로 다른 층을 다룬다.

| 항목 | 뜻 | 기록 시점·관할 |
|---|---|---|
| `lineage_stage` | 대상 revision이 작가 계보에서 어떤 발생 단계로 판독되는가 | 운영 프로토콜을 호출한 사후 계보 판독에서만 기록 |
| `current_engine_hypothesis` | 지금 시험할 극작 엔진 가설 | B2 설계·C1 집필 중 갱신 가능 |
| `observed_engine_layers` | 고정된 대상 revision에서 실제로 작동하는 엔진 층위 | C2 이후 사후 관찰 또는 운영 프로토콜 판독 |
| `six_domain_evaluation` | 6영역 100점 평가 결과 — 정의·앵커의 진실원은 [[wiki/writing/aesthetics/희곡_평가_교리|희곡 평가 교리]] §4 | 사용자가 100점 평가·외부 심사 시뮬레이션을 요청했을 때만 생성 |

- `lineage_stage`를 모르면 `not_assessed` 또는 `unknown`으로 남기며, 계보를 추정해 채우지 않는다.
- B2의 엔진 미고정은 설계 강제 금지다. C2 이후 엔진 층위를 재는 것은 완성된 본문에 대한 사후 관찰이다. 층위 수는 품질 점수도 계보 단계도 아니고, 다음 단계로 넘어갈 근거도 아니다.
- `블라인드 평가`는 운영 프로토콜의 채점 오염 방지 절차명으로 남긴다. R0의 역할별 가상 낭독은 `상호 비공개 독립 방 시뮬레이션`이라 부른다.
- 운영 프로토콜의 정확한 파일 경로가 현재 sources에 연결되지 않은 환경에서는 이름을 추정해 링크하지 않고, 평가 기록의 `protocol_ref`에 실제 문서명·판본을 확인한 뒤 적는다.

### 0.7 모든 희곡 평가의 연극적 약속·물성 표기 계약

희곡의 종합 평가, 퇴고·개작 판정, 피드백 번역, 가상 낭독·실연 결과에는 다음 한 줄을 빠뜨리지 않는다. 등급·소유 층위 정의의 단일 진실원은 [[wiki/writing/aesthetics/연극적_약속_물성_판정_카드#1. 모든 희곡 평가의 필수 표시|판정 카드 §1]]이며, 아래는 운영 요약이다. 평소 작업에서는 [[wiki/writing/aesthetics/집필_파이프라인_실행카드#0.5 모든 희곡 평가의 필수 표시|실행카드 §0.5]]가 같은 계약을 싣는다.

`[약·물] 약속=허용|P2|P1|P0|미평가 / 소유=해당 없음|본문|제작|기술|미평가 / 상세=OFF|ON`

- 물성 문제가 없거나 중심 판단을 바꾸지 않으면 `허용 / 해당 없음 / OFF`로 닫는다.
- 자료가 부족해 약속의 성립이나 소유를 가를 수 없으면 `미평가 / 미평가`로 숨기지 않고 남긴다.
- `P2` 이상이거나, 사물·공정·시간·시야·안전·리셋이 사건 또는 결말을 운반하면 `상세=ON`으로 두고 [[wiki/writing/aesthetics/연극적_약속_물성_판정_카드|판정 카드]]를 펼친다.
- 문제마다 약속 판정과 소유 층위를 따로 기록한다. `P1/본문(표면 계보) + P0/기술(젖은 바닥)`처럼 서로 다른 문제를 한 등급으로 뭉개지 않는다.
- `제작`은 합리적 상연안 선택, `기술`은 안전·큐·리셋 운용, `본문`은 일관된 상연 해법이 없는 서사 물리·약속 결함이다.
- 시간 조직이 관련되면 뒤에 `시간=엄격 리얼타임|대표·압축|혼합`을 붙인다(무관하면 `해당 없음`). enum 진실원은 [[wiki/writing/aesthetics/희곡_길이별_설계_원리#1.1 세 가지 시간 계약|길이 원리 §1.1]]의 기록값이다.
- 이 표시는 희곡을 물성 중심 미학으로 강제하지 않는다. `상세=OFF`가 정상적인 종결값이다.

## 1. 전체 지도와 진입 라우터

### 1.1 전체 지도

| 구간 | 질문 | 기본 산출 |
|---|---|---|
| 사이클 A — 채집·숙성·개발 선택 | 지금 무엇에 주의를 배정할 것인가 | 씨앗 기록 + A→B 이관 패킷 |
| 진입 라우터 | 새로 쓸 것인가, 이어 쓸 것인가, 퇴고할 것인가, 작품 동일성 계약을 바꿀 것인가 | 작업 원장 + 경로 판정 |
| 사이클 B — 구체화 | 무엇을 써보면 이 작품의 가능성을 가장 싸게 알 수 있는가 | 보호 기록 + 필요한 설계·소시험 |
| 사이클 C1–C2 — 조립 | 설계를 잊고도 한 편이 끝까지 살아 움직이는가 | 연결 초고 + 측정 |
| 사이클 C3 — 퇴고/개작 | 같은 작품 동일성 계약 안의 병목인가, 계약을 바꿔야 하는가 | 현재 기준판 + 개작 로그 |
| 사이클 C4 — 잠금 | 어떤 증거 수준으로 이 판본을 잠글 수 있는가 | 잠긴 판본 + 작품카드 |
| 환류 | 실제 낭독·제출·공연에서 무엇을 배웠는가 | 작품카드 갱신 + 재개 조건 |

사이클 A의 포착·숙성은 [[wiki/writing/aesthetics/히라타식_글감_채집_사이클|글감 채집·숙성 사이클]], 개발 선택·이관은 [[wiki/writing/aesthetics/글감_판정_루브릭|글감 다음 행동 루브릭]]에 정의한다. 사용자가 선택한 뒤의 탐색부터 B·C는 이 문서가 담당한다.

### 1.2 진입 라우터

기존 원고가 있으면 지정된 전체 범위를 먼저 읽는다. 일부 장면만 보고 완성도나 경로를 판정하지 않는다.

| 현재 자료 | 기본 진입 | 최소 확인 |
|---|---|---|
| 미선택 씨앗·메모 | 사이클 A | 원형 보존, 숙성·재접촉, 사용자 개발 선택 |
| 사용자가 지금 개발하기로 선택한 씨앗 | A→B 이관 후 B1 | 이관 패킷, 보호할 잔여, 사용자 표현의 끌림 |
| 장면 조각이 있으나 형식·시간 엔진이 미정 | B1 또는 B1.5 | 살아난 장면, 다음 행동을 만드는 힘 |
| 전체 초고가 있음, 성숙도 미판정 | C2 역산 판정 | 현재 작품 동일성 계약, 기준판 가능 여부, 상류 병목, 실연 위험 |
| 완성 판본의 특정 병목을 다룸 | C3 | 기준판과 승인 범위 |
| 잠긴 판본의 제출·상연 증거만 확인 | C4 증거 감사 | 잠긴 판본 동일성, 목표 요강 |
| 평가만 요청됨 | 상태 변경 없음 | 읽기 범위와 평가 질문 |

완성고가 B1–B4를 역주행하며 이미 존재하는 본문을 표로 다시 옮기게 하지 않는다.

작업 원장에 처음 편입하는 전체 초고는 먼저 C2 역산으로 읽는다. 이는 C2 자동 통과가 아니다. 핵심 엔진과 끝까지 읽을 수 있는 판본이 성립하면 기준판·측정을 만들고 C3로 가며, 성립하지 않으면 전체 독해에서 지목된 가설 층에 따라 C1 또는 B2로 회귀한다. 이미 기준판·작품카드가 등록된 작품의 특정 병목 재검토는 C3로 바로 간다.

평가만이 아니라 상태 작업을 시작하며 작업 원장에 처음 편입하는, 끝까지 연결된 전체 원고는 C2 역산 판정이 우선한다. 글감 루브릭·초고 전 체크리스트·B 설계를 소급 작성하지 않고, C2가 지목한 특정 상류 병목에 한해서만 해당 렌즈를 호출한다.

평가만 요청된 미등록 원고는 work_id나 상태를 만들지 않는다. 대상 파일·범위·가능하면 체크섬만 평가 헤더에 고정하고 읽기 전용으로 진단한다.

### 1.3 작품 동일성 계약과 퇴고/구조개작 판정

`작품 동일성 계약`은 현재판을 같은 작품으로 묶는 최소 약속이다. 구판의 `작품 계약`은 이 용어의 legacy alias다.

- 중심 상황과 대표 무대 장면
- 시공간 조직
- 중심 인물·관계 또는 목소리 배치
- 핵심 수행·지속·사건 운반 방식
- 관객이 기다리거나 발견하게 되는 것
- 결말이 가하는 힘

**퇴고**는 이 계약 안에서 정합성·행동·대사·리듬·물성·종막의 획득 과정을 고친다.  
**구조개작**은 계약 자체를 바꾼다.

판정이 어려우면 `중심 장면 생존 시험`을 한다.

> 가장 강한 장면이 같은 인물 관계와 기능을 유지한 채 새 판본에서도 중심으로 살아남는가?

- 살아남으면 퇴고 우선.
- 장면의 주체·기능·시간축·작품의 질문이 바뀌면 구조개작 후보.
- 구조개작은 부모판을 보존한 새 가지에서 B1/B2로 간다. 부모판을 덮어쓰지 않는다.

## 2. 판본 결박 (상태 계약은 2026-08-17 삭제)

> **삭제 기록.** 이 절에는 작업 원장의 branch 레지스트리, `canonical`/`candidate` 구분, child candidate branch, `lock_only`/`lock_and_promote`, `next_lock_number` 배정, `operation`(제출교정·증거감사), `workflow_phase` 5값과 전이표, `depth`/`module_depth`, `lineage_assessment`가 있었다. 109행이었다.
>
> **왜 지웠나.** 실사용 로그 언급이 0~1회였고, 작업 원장 5건 전부가 `canonical_branch: null` · `working_branch: main` · `next_lock_number: 1` · `operation: none` · `depth: 표준`이었다. 개인 창작 vault에 git-like 판본 관리를 얹은 것인데 **한 번도 분기하거나 승격한 적이 없다.** 없는 문제를 위한 기계가 문서의 8분의 1을 쓰고 있었다.
>
> **되살려야 할 때.** 다판본 병행 개발, 공모별 서로 다른 잠금본, 연작 편별 독립 판본 관리가 실제로 필요해지면 이 문단을 근거로 다시 설계한다. 그때도 **먼저 필요를 확인하고 나서** 만든다.

살아남은 것은 하나다 — **판본 결박**. 이것은 2026-08-17 보정 실험에서 실제로 사고를 막았다(워킹트리 파일을 그냥 썼다면 3,685자 자란 개작본을 옛 점수와 비교할 뻔했다).

- 평가·낭독·측정·게이트 기록은 대상 파일 경로와 **체크섬**을 적는다.
- 외부 낭독·C4·판본 비교 전에는 반드시 체크섬을 만든다. 못 만들었으면 `not_done`으로 남기고 숨기지 않는다.
- 잠근 파일은 덮어쓰지 않는다. 수정은 새 파일에서 하고, 작품카드의 잠금 목록이 유일한 대장이다.
- 선행 판본의 평가·낭독·측정을 후속판에 재사용할 때는 **영향받은 장면·물성·시간 조직·결말이 바뀌었는지 다시 본다.**
- 작품별 지속 정보(진행 여부·AI 이용 이력·공모 자격·검증 증거)는 [[wiki/writing/aesthetics/집필_파이프라인_실행카드#10. 작업 원장 — 작품당 하나|실행 정본 §10]]의 간소 양식을 쓴다.

## 4. 사이클 B — 구체화

**입력**: 사용자가 지금 개발하기로 선택하고 A→B 이관 패킷이 붙은 새 글감, 미완 원고, 또는 구조개작 가지.  
**출력**: C1에서 무엇을 발견할지 아는 `대기` 상태의 설계.

실행 순서는 `B1 보호 → B1.5 탐색 → 필요시 잠정 형식 비교 → B2 맵에 선택 기록 → 필요시 연작 공통·B3 → B4 게이트`다.

### B1. 보호와 현재 중심 가설

교리보다 먼저 다음을 기록한다.

A→B 이관 패킷이 있으면 `seed_snapshot_ref`로 참조하고 같은 내용을 다시 옮겨 적지 않는다. 아래 항목 가운데 B 진입 뒤 새로 생기거나 달라진 것만 delta로 기록한다.

- 지금 붙드는 사람·목소리·이미지·상황
- 왜 끌리는지 아직 설명하지 못하는 부분
- 쓰면서도 모르고 싶은 것
- 작품이 작가를 놀라게 할 수 있는 자리
- 가장 강한 행동 또는 지속
- 익숙해서 자동으로 고를 위험이 있는 장치
- 안전·권리·출처의 경계

처음부터 완성된 관객 시간 약속이나 작품 정의를 요구하지 않는다. 현재 보이는 만큼만 `현재 중심 가설`을 쓴다.

#### 운반체·부품

- 계열 지도의 경합이 있으면 후보를 비교하고 사용자가 운반체를 정한다.
- 부품은 `쓸 것 / 시험할 것 / 보류 / 반환`으로 나눈다.
- 많은 부품을 쓰는 것이 발전은 아니다.

#### 형식 비교 — 병목일 때만

짧은 쓰기나 조사 뒤에도 자연 규모와 시간 조직이 병목일 때 2–3안을 비교한다.

| 기록 | 후보 A | 후보 B | 후보 C |
|---|---|---|---|
| 자연 규모 가설 |  |  |  |
| 시간을 만드는 연료 |  |  |  |
| 보호되는 것 / 잃는 것 |  |  |  |
| 새 행동·관계·관객 경험 |  |  |  |
| 제작·설명·후속 비용 |  |  |  |
| 실패 시 가장 싼 회귀 |  |  |  |
| 판정 | 선택 / 병렬 소시험 / 보류 / 기각 |  |  |

가장 작은 독립 완결 후보를 포함하되, 특정 규모를 기본값으로 넣지 않는다. 규모 이름과 규격 밖 이탈의 기록 규약은 [[wiki/writing/aesthetics/희곡_길이별_설계_원리|길이 원리]] §4.0을 따른다 — 규격 밖 후보(다인·다공간·시간 비약의 1막 등)를 비교에 올리는 것은 정상이며, 선택되면 이탈로 기록한다.

#### 외부 제약과 AI 이용

- 자연 규모와 `submission_target`을 다른 칸에 쓴다.
- 목표 공모가 있으면 공식 요강의 AI 규정을 `허용 / 공개 조건부 허용 / 금지 / 불명`으로 기록하고 출처와 확인일을 남긴다.
- `불명`이면 그 공모를 목표로 한 추가 AI 개입을 멈춘다.
- 구조·평가·교정도 AI 이용에 포함될 수 있으므로 자동 허용하지 않는다.
- AI 이용 범위와 본문에 남은 생성 문장을 숨기거나 소급해 “사용자 단독”으로 바꾸지 않는다.

```yaml
ai_provenance:
  - date:
    model:
    operation:
    affected_revision:
    affected_paths: []
    generated_text_retained:
contest_eligibility:
  target:
  rule_source:
  checked_at:
  status: eligible | disclosure_required | unclear | ineligible
  disclosure_terms:
```

`ai_provenance`는 append-only이며 revision에 묶는다. 현재 `ai_mode`를 바꿔 과거 이용을 덮어쓰지 않는다. 목표 공모 제출 잠금은 `eligible`이거나 요구된 공개 조건을 이행한 `disclosure_required`일 때만 허용한다.

### B1.5. 가장 싼 탐색

핵심과 장면 생성 원리가 이미 보이면 생략한다. 독립된 위험이 둘이면 소시험도 둘까지 병렬로 할 수 있다.

| 실제 병목 | 우선 탐색 | 판정 질문 |
|---|---|---|
| 사람·대사·관계 | 2–5쪽 장면, 대화/독백 조각 | 이 사람의 다음 말·침묵을 더 보고 싶은가 |
| 사건·우연·정서 | 대표 장면 한 개 | 사건을 설명하지 않고 삶의 흔들림이 보이는가 |
| 시간 연료·장면 연결 | 비트 스케치, 장면쌍, 형식별 짧은 샘플 | 반복·도약·교차·지속이 다음 조건을 만드는가 |
| 공간·거리·오브제 | 안전한 모형·동선·소리 시험 | 말 없이 알아야 할 조건이 객석에서 읽히는가 |
| 배우의 수행 | 음독, 행동 동사 시험, 짧은 블로킹 | 배우가 심리가 아니라 행동으로 붙들 수 있는가 |
| 관객 주의 | 전경/배경 스코어, 사전정보 미제공 독자 질문 | 무엇을 기다리고 언제 다시 보게 되는가 |
| 출처·윤리·사실 | 조사, 허구화 경계 카드 | 원천 표면을 소비하지 않고 독립 장면이 되는가 |

소시험마다 `질문 / 관찰 / 살아난 것 / 반증된 것 / 다음 결정`만 남긴다.

`blocked`인 씨앗의 미해결 권리·사생활·안전 문제는 B1.5로 우회하지 않는다. 차단 해제를 위한 좁은 사실·권리 확인은 사이클 A에서 할 수 있으며, `clear` 또는 `resolved`가 된 뒤 A→B 이관한다. B1.5의 출처·윤리 조사는 이관 가능한 원천의 허구화 거리·사실 정확성·독립성을 탐색하는 단계다.

### B2. 최소 구조 맵

#### B2-1. 공통 핵심

표를 모두 채우지 말고 아래 다섯 질문에 답한다.

1. **무대 상황** — 필연·우연·설명되지 않은 공존을 포함해 이 상황은 무대에서 어떻게 시작되고 지속되는가.
2. **사람과 행위** — 누가 누구에게 무엇을 원하고, 피하고, 지키고, 말하지 못하는가. 인물이 적거나 없으면 어떤 목소리·몸·이미지가 지속되는가.
3. **진행 가설** — 무엇이 귀환·축적·교체·분산·소진되거나 의도적으로 정체되는가.
4. **무대 경로** — 몸·사물·소리·빛·매체가 어떻게 사건을 운반하는가.
5. **관객 경험** — 관객의 주의·정서·기대는 어떻게 머물거나 이동하거나 흩어지는가. 작품은 어떻게 멈추거나 계속되거나 끊기거나 흩어지는가.

맵의 목적은 전체 본문을 미리 쓰는 것이 아니다. 다음에 쓸 수행 단위와 잠정적 진행 가설이 있으면 충분하다.

#### B2-2. 극작 엔진 선택

현재 보이는 엔진을 필요한 만큼만 고른다. `단일 / 혼성 / 교대 / 붕괴·소진 / 분산 / C1에서 판별` 가운데 현재 가설을 적을 수 있으며, 엔진 수와 지속을 미리 고정하지 않는다. 선택하지 않은 엔진은 게이트가 아니다.

여기서 적는 것은 `current_engine_hypothesis`다. 아직 쓰이지 않은 엔진 수를 목표값으로 만들거나, 복수 엔진을 더 높은 성숙도·점수로 간주하지 않는다. C2 이후의 `observed_engine_layers`는 고정된 revision을 끝까지 읽고 실제 작동층을 기술하는 별도 사후 관찰이다.

| 엔진 | 설계 증거 |
|---|---|
| 관계·욕망 | 원하는 것, 요구하지 못하는 것, 오해·도움·목격·접촉의 변화 |
| 사건·운명·우연 | 삶을 흔드는 사건과 그것이 응축되는 대표 무대 장면 |
| 정서·정신 진폭 | 억눌리거나 지나치던 정서가 몸·말·거리에서 보이는 경로 |
| 이미지·감각·지속 | 반복·정체·기다림이 관객 지각을 바꾸는 방식 |
| 절차·제도 | 규칙·분류·기록·권한이 사람의 행동을 바꾸는 방식 |
| 언어·목소리 | 말투·호명·리듬·발화 형식 자체의 진행 |
| 의례·놀이·수행 | 함께 하는 행위의 규칙·실패·변형이 관계를 드러내는 방식 |

세미퍼블릭 공간과 작은 절차는 유용한 선택이지 우수성 기준이 아니다. 사적·공적·빈 장소, 큰 사건, 우연한 만남도 작품의 필요라면 선택한다. 큰 사건은 축소하지 말고 그 여파가 응축되는 대표 무대 장면을 고른다.

#### B2-3. 전용수 계열 모듈 — 호출될 때만

- 공식 언어 ↔ 사적 언어
- 절차·기록·분류·명명 불가
- 화면 ↔ 오브제, 현재 ↔ 기억
- 침묵 ↔ 범람
- 해결 유보와 사물·소리의 잔여

이 모듈들은 작가의 중요한 서명이지만 모든 작품의 보편 법칙은 아니다. 보호 기록과 현재 선택한 엔진이 호출할 때만 적용한다.

#### B2-4. 시간·형식 모듈

F 정의의 단일 진실원은 [[wiki/writing/aesthetics/희곡_길이별_설계_원리#2. F1–F5 — 시간 조직 어포던스 (단일 진실원)|희곡 길이·시간 조직 설계 원리 §2]]다. 각 코드의 뜻·성립 조건·무너지는 지점, F4/F5 판정선, 오용 방지는 그 절에 있다. 아래 표는 현재 작품에 필요한 증거를 요약할 뿐 코드를 재정의하지 않는다.

| 형식 어포던스 | 필요한 증거 |
|---|---|
| 최소 자연 규모 | 핵심 수행·지속·이미지 경로가 독립적으로 멈추는 이유 / 더 길면 필요한 새 연료 |
| F1 연속 체류·수평 | 체류·재진입 이유 / 출입·조합 변화 / 대기·정리·이동의 결과 |
| F2 수직 반복 | 귀환점 / 반복 묶음별 기능·비용·관계·몸·사물·관객 해석의 변화 |
| F3 다중 흐름 | 흐름별 독립 변화 / 교차 / 전경·배경·주의 배분 |
| F4 종축·인과·몽타주 | 기다림–부분 성취–예상 밖 결과–다음 조건 / 국면 전환 |
| F5 불연속·연작 | 단위별 독립 완결 / 편간 간격 / 상속·변형 / 전체 순서 효과 |

F1–F4는 길이대와 일대일 대응하지 않는다. 결합형도 가능하다. 반복 사이의 일부 비트는 모든 순간에 새 정보를 만들지 않아도 망설임·박자·상대 반응을 형성할 수 있다.

#### B2-5. 연작 공통 — F5를 선택했을 때만

`draft-candidates/<연작>_연작공통.md`에 기록한다.

- 공유 물성의 단일 사양과 편별 변형
- 각 편의 독립 행동·완결
- 앞 편에서 물려받고 뒤 편에 넘기는 것
- 시간·세대·장소 간격과 전체 순서 효과
- 현재 활성 편, 잠긴 편 수, 연작 전체 검증 상태

편이 독립 공연 불가능하고 앞 국면의 선택이 뒤를 필연적으로 제한하면 F4 장막 구조인지 다시 본다.

### B3. 물성·언어·매체 문서 — 조건부

- `<작품>_대사_어휘표.md`
- `<작품>_<대상>_물성표.md`
- 동작·리듬·음향·조명 규칙표
- 동시 대사·화면·자막 표기 규약
- `연극적 약속·물성 판정 카드` — 상세 가동 조건이 충족될 때만

별도 문서는 그것이 실제 장면 생성 장치이거나 제작 위험을 관리할 때만 만든다. B2 안에서 충분하면 생략한다.

### B4. 착수 게이트

#### B4-1. 공통 게이트

| 축 | 통과 질문 |
|---|---|
| 쓰기 충동 | 작가가 아직 이 작품을 쓰고 싶은가 |
| 살아 있는 핵 | 사람·목소리·이미지·행동·지속 가운데 적어도 하나가 살아 있는가 |
| 착수 단위 | 다음에 쓸 행동·지속·목소리·이미지의 수행 단위가 있는가 |
| 진행 가설 | 무엇이 귀환·축적·교체·분산·소진·정체되며, 그 가설을 C1에서 어떻게 시험할 것인가 |
| 배우·관객 경로 | 배우가 수행할 것과 관객이 지각할 경로가 있는가 |
| 위험 | 관리되지 않은 비가역 가정이 없는가 |
| 규모 | 자연 규모와 외부 규격을 분리했는가 |
| 권리·AI | 출처·윤리·안전·AI 이용의 현재 경계를 기록했는가 |

선택한 극작 엔진과 형식 모듈의 질문만 추가한다. 선택하지 않은 정보 차이·대항력·제도·물성·미결 결말을 요구하지 않는다.

원작·실화·책을 재해석하는 경우에만 `원작을 몰라도 독립하는가 / 알면 다른 층위가 열리는가 / 권리·출처·피해 재현의 거리가 적절한가`를 추가한다.

판정값은 `pass / fail / waived / not-applicable`이다. `waived`는 창작적 위험을 알고 감수할 때만 쓰며 안전·권리·출처·공모 자격은 면제할 수 없다.

#### B4-2. 가정 분류

| 분류 | 예 | 처리 |
|---|---|---|
| 비가역·차단 가정 | 권리·안전·윤리·공모 자격, 핵심 수행의 물리적 불가능, 감당 불가능한 제작비 | C1 전 해소 |
| 가역적 구조 가설 | 시간 엔진, 일부 인물 배치, 장면 순서 | C1 시험과 실패 시 회귀 경로 지정 |
| 리허설·제작 가정 | 카드 시야, 화면 크기, 동선, 음향 레벨 | C1 허용, C4 전 실제 시험 |
| 쓰기 발견 항목 | 어휘, 세부 관계, 결말 후보, 리듬 | 이름만 붙이고 C1 허용 |
| 의도된 해석적 열림 | 진술 상대, 침묵의 의미, 복수 해석, 미결 결말 | 보호 대상 |

통과 조건은 `열린 가정 0건`이 아니라 **관리되지 않은 비가역·차단 가정 0건**이다. 가역 가설은 시험 시점과 실패 시 회귀 경로를 가진다.

> **가정 노출 방어 조항**  
> 이 분류의 목적은 열려 있는 것을 모두 닫는 데 있지 않다. 무엇이 비가역 위험이고 무엇이 쓰기·리허설에서 시험할 가설인지 드러내기 위한 장치다. 진술 상대, 침묵의 의미, 복수 해석, 미결 결말처럼 작품이 의도한 열림을 폐쇄하라는 요구로 이 절을 사용하면 오용이며, 그 열림 자체가 보호 대상이다.

#### B4-3. 출발 스냅샷

B4 통과 시 원본을 고치지 않는 `출발 스냅샷`을 남긴다.

- 붙들었던 사람·이미지·행동
- 당시의 온도
- 당시의 장면 생성 가설
- 보호하려던 윤리 경계
- 열어두기로 한 것

A→B 이관 패킷이 있으면 `seed_snapshot_ref`로 참조하고 같은 내용을 다시 쓰지 않는다. B1·B1.5에서 새로 생긴 중심 가설, 행동, 윤리 경계만 덧붙인다.

동결되는 것은 **과거 기록**이지 작품의 의무가 아니다. 작품이 출발점을 배반한 것이 첫 발견일 수 있다. 별도의 `현재 중심 가설`은 갱신할 수 있다.

스냅샷 대조는 매 회차가 아니라 다음 세 번만 한다.

1. C2 연결 초고 성립
2. 대수술·구조개작 분기
3. C4 상정

판정은 `중요한 것을 잃음 / 더 살아 있는 것을 발견함 / 둘이 긴장한 채 공존함`으로 기록한다.

B4 통과 기록은 현재 `design_revision`과 branch에 묶고 `대기`로 승격한다.

## 5. 사이클 C — 집필·퇴고·개작

C의 보편 기준은 다음 다섯 가지다.

- 조건이 말·침묵·행동을 실제로 낳는가
- 배우가 수행할 수 있고 관객이 지각할 수 있는가
- 해설과 수행을 구분하는가
- 관계·정서·몸·리듬·물성이 작품의 필요에 따라 살아 있는가
- 쓰기 발견이 설계를 수정할 권리를 갖는가

`공식 언어와 사적 언어`, `절차`, `명명 불가`, `범람`, `미결 잔여`는 선택한 작품에서만 전용수 계열 렌즈로 적용한다.

### C1. 무감사 조립

#### 무감사 집필 구간

사용자가 정한 첫 정지점까지 구조표·스냅샷·기능감사·점수표를 재호출하지 않는다.

- 한 장면
- 한 시퀀스
- 하나의 반복 묶음
- 연속 초고 스프린트
- 첫 연결본

가운데 하나를 정지점으로 고른다. 안전·권리 침해나 핵심 수행의 명백한 물리적 불가능만 즉시 중단 사유다. 맵과 다른 인물·관계·결말이 나와도 바로 회귀하지 않는다.

스프린트 뒤 네 줄만 남긴다.

1. 계획과 같았던 것
2. 새로 발견한 것
3. 설계를 반박한 것
4. 더 따라가고 싶은 것

#### 조립 원칙

- 가장 확신 있는 장면부터 비선형으로 써도 된다.
- 장면마다가 아니라 사용자가 정한 스프린트·시퀀스·연결본 정지점에서 `무엇이 달라졌거나, 깊어졌거나, 버텼거나, 새로 보이게 되었는가`를 묶어 본다.
- 상태 변화가 없다면 지속·정체·반복이 관객의 주의와 정서를 바꾸는지 본다.
- 그것도 없다면 문장보다 현재 진행 가설과 무대 상황을 먼저 본다.
- 목표 매수에 가까워졌다는 이유로 결말을 서두르지 않는다.
- 필요한 행동·관계·정서·감각·지각의 축적이 더 남아 있으면 계속 쓴다.

장면 초안은 `draft-candidates/`, 현재 연결 원고는 `drafts/`에 둔다. 분할이 작업을 방해하는 최소형·독백·단일 수행은 처음부터 연결본으로 써도 된다.

### C2. 연결 초고 게이트

#### 내용 조건

- 작품이 붙든 사람·목소리·이미지·행동·지속 가운데 적어도 하나의 경로가 처음부터 끝까지 경험된다.
- 선택한 엔진이 끝까지 지속되거나, 다른 엔진으로의 교체·분산·붕괴·소진이 의도된 전환으로 읽힌다.
- 작품이 필요로 하는 관계·정서·몸·사물·관객 지각의 경로가 연결된다.
- 결말이 확정되지 않았더라도 끝까지 읽을 수 있는 판본이 있다.

파일명보다 작업 원장의 `current_revision` 지정이 우선한다. C2 통과 revision은 이후 평가와 측정의 기준판으로 보존한다.

#### 설계 시점과 사후 엔진 판독

- B2에서는 엔진 수·지속을 미리 고정하지 않는다.
- C2에서는 고정된 대상 revision이 실제로 사용한 엔진과 그 관계를 `observed_engine_layers`에 `단일 / 혼성 / 교대 / 분산 / 붕괴·소진` 등으로 서술할 수 있다.
- 같은 방식으로 실제 작동한 시간 조직을 `observed_form_affordances`에 F1–F5로 서술할 수 있다. **선택 필드이며 의무가 아니다.** 엔진 층위와 마찬가지로 개수는 점수가 아니다.
- 운영 프로토콜이 엔진 층위 수를 요구하면 대상 revision·판독 근거·프로토콜 판본을 함께 기록한다.
- 층위 수는 설명 변수이지 우수성 점수가 아니다. 많거나 적다는 이유로 6영역 점수를 가감하거나 `lineage_stage`를 올리지 않는다.

#### 측정

| 항목 | 기록 |
|---|---|
| 관찰 원고지 매수 | 도구·날짜 |
| 객석시간 실측 범위 | **범위로 적는다**(점추정 금지) + 근거 등급(R1/R2/R3/R4). 기록 규약은 길이 원리 §4.1 |
| 예상 발화 시간 | 추정 근거 |
| 예상 비언어 시간 | 침묵·노동·이동·빛·전환 |
| 자가 음독 시간 | 독자·날짜·중단 여부 |
| 외부 테이블리딩 시간 | 참여자·날짜·중단 여부 |
| 동선·오브제 런 시간 | 시험 구간·조건 |
| 기술 런·공연 시간 | 공간·기술 조건 |
| 현재 자연 규모 | 짧게 완결 / 유지 / 확장 / 분할 |
| 외부 제출 규격 | 목표가 있을 때만 |

가상 낭독은 실제 발화·공연 시간 칸에 넣지 않는다.

#### C2 재판정

- 출발 스냅샷과 현재판: 잃음 / 발견 / 긴장
- 작품 동일성 계약: 유지 / 퇴고로 해결 / 구조개작 필요
- 현재 자연 규모
- 상류 병목 1–3개
- 아직 검증하지 못한 실연 위험
- `[약·물]` 필수 한 줄과 상세 카드 가동 여부

익숙한 자동 해결법이 의심되거나 사용자가 계보 비교를 요청할 때만 자기복제를 본다. 최근 가까운 작품 2–3편과 장소, 관계, 압력 출처, 언어 리듬, 핵심 장치, 결말 기제를 비교한다.

- **작가적 서명**: 같은 질문이 새로운 사람·관계·정서·윤리 결과를 낳음.
- **자동 해결법**: 새 필요 없이 익명 인물·양식·화면·절삭 발화·사물 잔여가 반복됨.

필요할 때만 한 작품에 한해 회전식 금지 실험을 건다. 반복되는 핵심 관심 자체를 지우지는 않는다.

자기복제 비교는 반복되는 **해결법**을 찾는 계보 진단이다. 신작과 구작의 우열 비교, 작가적 서명 유무에 따른 점수 보정, 새 작품을 옛 작품에 가깝게 만드는 처방으로 사용하지 않는다.

### C3. 퇴고·구조개작과 잠금판 보조 작업

#### C3-0. 수정 방식 판정

| 구분 | 조건 | 경로 |
|---|---|---|
| 퇴고 | 작품 동일성 계약 유지 | C3 안에서 수정 |
| 구조개작 | 작품 동일성 계약 변경 필요 | 부모판 보존 → 새 파일 → B1/B2 |
| 잠긴 판본 본문 수정 | 같은 작품 동일성 계약의 다음 후보 | 잠금판 vN 보존 → 새 후보 파일 → C3 |
| 제출교정 | 잠긴 본문은 유지, 요강·파일·메타데이터만 정비 | 본문 변경이 생기면 그때 새 후보로 퇴고 |
| 증거감사 | 잠긴 본문은 유지, 낭독·물성·기술 증거만 확인 | 새 P0가 본문 수정을 요구하면 새 후보로 퇴고 |

`revision_mode`는 퇴고면 `퇴고`, 구조개작이면 `구조개작`이다. 제출교정·증거감사는 본문을 건드리지 않으므로 `revision_mode`를 만들지 않는다.

**잠긴 판본은 무슨 일이 있어도 그 자리에 남는다.** 본문을 다시 열 때는 언제나 새 파일에서 시작하고, 잠금판 vN과 그 체크섬은 보존한다.

#### C3-1. 승인 봉투와 회차

회차 시작 시 한 번 정한다.

```yaml
target_revision:
output_revision:
scope:
purpose:
upstream_bottlenecks: []
allowed_operations: []
protected: []
requires_new_approval: []
coverage:
```

한 회차는 `기준 revision + 승인 범위 + 수정 묶음 + output revision + 측정/판정`이다. 한 턴 한 장면을 강제하지 않는다. 장면, 시퀀스, 영향받는 여러 장면, 진단 묶음 가운데 실제 병목에 맞는 단위를 고른다.

별도 문서 세 개를 상시 만들지 않고 하나의 append-only 개작 로그에 기록한다.

- 기준판과 목적
- 상류 병목 1–3개
- 바꾼 범위와 함께 달라지는 하류 요소
- 수용·기각·보류한 피드백
- 되돌린 수정
- 측정과 현재 증거 수준
- 다음 판단

기능감사·전면 체크리스트는 C2, C4 상정, 구조 회귀, 외부 낭독 직후, 또는 특정 병목이 있을 때만 분리한다.

##### 6영역 평가 호출 계약

평가 서식·6영역 정의·점수 앵커·익명 비교 절차의 단일 진실원은 [[wiki/writing/aesthetics/희곡_평가_교리|희곡 평가 교리]]다(2026-08-17 제정 — 그 전에는 이 계약이 정의 없는 루브릭을 참조하고 있었다). 아래는 호출 조건의 운영 요약이다.

- 사용자가 100점 평가, 공모 심사 시뮬레이션, 또는 특정 외부 루브릭 적용을 명시적으로 요청했을 때만 연다.
- 대상 revision, 사용한 6영역 정의·배점·판본, 평가 목적을 헤더에 고정한다. 공모별 루브릭이면 보편 100점표와 섞지 않는다.
- 결과는 읽기 전용 평가층이다. 잠금·C4 통과·작품 동일성 계약 변경을 자동으로 일으키지 않는다.
- 엔진 층위 수, `lineage_stage`, 전용수다운 정도, 기존 작품과의 유사성은 가산·감점 항목이 아니다. 외부 루브릭이 이를 명시할 때만 해당 외부 기준으로 별도 표시한다.
- 평가자가 계보·프로토콜 판본을 확인하지 못했으면 관련 항목은 `not_assessed`로 남기고 추정하지 않는다.
- 6영역 점수와 무관하게 `[약·물] 약속 판정 / 소유 층위 / 상세 가동 여부`를 한 줄로 표시한다. 이는 별도 가산·감점 항목이 아니라 물리·제작 책임의 귀속 기록이다.

#### C3-2. 수정 순서

수정은 선택한 엔진이 위치한 층에서 시작한다. 아래 순서는 구조 병목일 때의 기본값이며 언어극에서는 리듬, 수행극에서는 몸·물성이 상류일 수 있다.

1. 작품 동일성 계약·형식·시간 조직
2. 대표 장면과 인물 관계·행동·정서
3. 장면 간 축적과 관객 주의
4. 대사·침묵·리듬
5. 물성·동선·시야·기술 큐
6. 표기·오탈자·제출 형식

설명 대사는 장소 → 관계·욕망·사건 → 정보·감각 차이 → 물질 경로 → 그래도 필요한 말인가 순서로 본다. 직접 발화·닫힌 결말·범람은 앞선 행동이 벌어들였다면 보호한다.

#### C3-3. 낭독·실연 증거

> **이 표가 증거 등급 `H1 / R0–R4`의 단일 진실원이다.** 실행카드 §7과 피드백 번역 §2.1은 운영 사본이며, 등급의 뜻·알 수 있는 것·알 수 없는 것을 그쪽에서 바꾸지 않는다. 증거 등급은 C4 잠금을 좌우하는 강행 규약이므로 표현이 갈리면 실측 기록이 누락된다.

| 등급 | 증거 | 알 수 있는 것 | 알 수 없는 것 |
|---|---|---|---|
| H1 | 실제 독립 인간의 묵독·서면 피드백 | 자유 회상, 정보 누락, 독자별 오독·질문 | 발화성·배우 간 리듬·실연 시간·신체 |
| R0 | AI 가상 낭독·상호 비공개 독립 방 시뮬레이션 | 오독 후보, 자유 회상 가설, 이해관계자별 병목, 질문 설계 | 실제 발화성·시간·신체·객석 반응 |
| R1 | 사용자/작가 자가 음독·녹음 | 해당 독자의 발화 시간, 문장 걸림, 자기 청취 차이 | 외부 관객 이해, 배우 간 리듬 |
| R2 | 실제 외부 테이블리딩 | 배우 발화성, 상호 리듬, 청자 회상, 낭독 시간 | 본격 동선·물성·기술 |
| R3 | 동선·오브제 런 | 비언어 시간, 물성 경로, 시야, 신체 비용 | 완성 기술환경 |
| R4 | 기술 런·공개 낭독·공연 | 실제 포함된 기술·동선·관객 조건의 반응과 시간 | 포함되지 않은 조건, 다른 캐스팅·공간으로의 일반화 |

- R0는 유용한 진단이지만 외부 낭독으로 세지 않는다.
- H1은 실제 인간 독자 증거지만 R2의 발화·상호 리듬 증거를 대체하지 않는다.
- 가상 낭독자 여러 명은 R0 한 회차의 복수 시뮬레이션이다.
- 발화·공연 실측은 해당 R1–R4 조건과 함께 기록한다.
- R4는 `tech_run / public_reading / performance` subtype과 실제 포함된 기술·동선·관객 조건을 적는다.
- 다중 가상 낭독은 배우실·첫 관객실·연출/기술실을 독립시켜 합의보다 차이와 오독 회복을 보존한다.

#### C3-4. 실연 연속성 패스 — C4 전 필수

각 항목은 `문서상 확인 / 실제 시험 / 미확인 / not-applicable`로 기록한다. 핵심 결말 물성·안전·상연 가능성의 고위험 항목이 `미확인`이면 C4를 막는다.

`[약·물] 상세=ON`이면 판정 카드의 `관객 판단 → 네 층 → 약속 지도 → 네 시계 → 최종 귀속` 순서로 먼저 분해한다. 현실 공정의 전면 미복제만으로 본문 결함을 만들지 않는다.

- 오브제의 위치·방향·앞뒤·열림/닫힘·파손·소모 상태
- 문·벽·게시판·화면의 시야와 객석 가독성
- 배우의 손 점유, 휴대전화·충전선·조명·소품 조작 가능성
- 출입·이동·대기·침묵 중 다음 큐가 가능한가
- 음향·조명·영상 큐의 선후와 운영 주체
- 비언어 시간과 배우의 신체 비용
- 안전·권리·기술 의존성

핵심 물성이 결말을 운반하면 짧은 작품도 R3까지 올린다.

#### C3-5. 수렴과 회귀

| 신호 | 관측 | 우선 판단 |
|---|---|---|
| 수렴 | 전편 또는 영향 범위를 다시 읽은 연속 2회차에서 새 상류 병목이 없고 국소 수정만 남음 | C4 상정 |
| 진동 | 같은 대목을 고쳤다가 되돌리는 왕복이 2회 이상 | 취향 경합인지 계약 문제인지 판정 |
| 공전 | 같은 상류 병목이 3회 연속인데 하류 증상만 수정 | B2 또는 B1 회귀 |

회차가 전체 수렴으로 계산되려면 범위를 충족해야 한다.

- 최소형·단막: 전편 재독
- 장막(막이 있는 경우): 수정 영향권의 막 전체 재검토
- 장막(무막·단일 막): 막 경계가 없으므로 **수정 영향권의 장면 분절 묶음** 또는 전편 재독. 장막에서 막은 필수가 아니다([[wiki/writing/aesthetics/희곡_길이별_설계_원리#4.2 장막 — 실작 대조|길이 원리 §4.2]]) — 범위를 정하지 못하면 전편 재독으로 계산한다
- 연작: 편별 수렴과 전편 순서 수렴을 분리
- 규격 밖 이탈작·범위 미정: **전편 재독**이 기본 폴백

#### 회귀 사다리

| 발견 | 이동 | 기존 본문 | 무효화/재확인 |
|---|---|---|---|
| 대사 리듬·국소 명료성·큐·글자 크기·동선 | C3 유지 | 현재 revision에서 새 revision 생성 | 영향받은 증거만 |
| 같은 형식 안에서 진행 가설·관계·물질 경로 실패 | B2 | 증거판 보존 | B4·C2 |
| 자연 규모·인물 수·시공간·주 형식 변경 | B1 | 새 branch로 분기 | B4·C2·관련 낭독 |
| 편별 독립성과 장막 종속성 판정 변경 | 연작 공통/B1 | 기존 편 보존 | 연작 전체 설계 |
| C4 P0 미해결 | C3 | 후보판 유지 | C4만 |
| 잠긴 작품의 같은 작품 동일성 계약 재개 | 새 후보 파일의 C3 | 잠금판 vN 유지 | 다음 잠금용 C2/C4 |
| 잠긴 작품의 작품 동일성 계약 변경 재개 | 새 후보 파일의 B1 | 잠금판 vN 유지 | B4/C2/C4와 관련 낭독 |

회귀는 문제의 크기가 아니라 **어느 층의 가설이 반증됐는가**로 정한다.

### C4. 잠금 게이트

잠금은 “실제 공연으로 검증됨”이 아니라 **정확한 판본이 잠겨 상연·낭독·제출 후보가 됨**을 뜻한다. 실제 검증 수준은 별도 기록한다.

#### 잠금 근거

| 잠금 목적 | 최소 증거 |
|---|---|
| 텍스트·공모 제출 잠금 | R1 전편 + 적용 가능한 실연 연속성 패스. 특정 오독·관객 정보·구조 질문이 남으면 R0 또는 H1 추가 |
| 낭독·공연 준비 잠금 | R2 전편 + 핵심 물성이 있으면 R3 |
| 기술 의존 작품 | R2 + 핵심 구간 R3, 가능하면 R4 |

R2 외부 테이블리딩 없이 잠그면 `external_table_read_R2: not_done`을 숨기지 않는다. H1 독립 인간 묵독이나 R1 자가 음독을 R2로 올려 적지 않는다. 안전·권리·물리적 상연 불가능 문제는 창작적 면제로 넘길 수 없다.

#### 통과 조건

1. 후보 revision이 고정되어 모든 평가·낭독·측정이 그 판본에 결박돼 있다. 선행판 증거는 그 사이 바뀐 부분이 그 증거를 무효로 만들지 않았음을 확인한 것만 쓴다.
2. P0가 없다. P0는 안전·권리·출처 문제, 물리·인과 명료성 때문에 상연이 불가능한 지점, 선택한 작품 동일성 계약을 무너뜨리는 지점이다.
   - `P0/기술`은 현재 구현의 공연 준비 잠금을 막지만 자동 본문 결함은 아니다. 안전한 대안이 확인되면 새 구현으로 다시 시험한다.
   - `P0/본문`은 안전하고 반복 가능한 대안이 없고 본문이 해당 위험·인과 실패를 강제할 때만 성립한다.
3. 실연 연속성 패스를 완료했다.
4. 잠금 목적에 맞는 낭독·실연 증거가 있다.
5. 출발 스냅샷과 현재판의 관계, 자연 규모, 잠금 사유를 기록했다.
6. 목표 공모가 있으면 최신 공식 요강의 분량·마감·AI·판권·미발표·무기명·파일·시놉시스 규정을 다시 확인했다.

#### 잠금과 전달

- 잠금판은 `<작품>_v<N>.md/hwp` 정수 버전으로 만든다.
- 잠금 뒤 본문 변경은 새 후보 파일에서만 한다. 잠금 번호는 작품 전체에서 하나의 오름차순이며, 새 잠금판이 실제로 생길 때만 증가한다.
- `_낭독용 / _합평용 / _연출안`은 `derived_from: vN`을 기록한다.
- 파생판에 실질적 본문 변경이 생기면 새 잠금 후보로 승격한다.
- 제출 파일은 열림 여부, 익명성, 메타데이터, 제목·페이지·폰트·파일명, 요구 부속물을 최종 점검한다.

잠금은 원장의 `locked_versions`에 한 줄을 추가하는 사건이다. 어느 판본을 지금 기준으로 삼을지는 원장의 `current_revision` 한 필드로 정하며, **사용자 승인 없이 바꾸지 않는다.**

> **삭제 기록.** 이 절에 있던 `lock_only` / `lock_and_promote` 이원 사건, `canonical_branch` 포인터 전이, `next_lock_number` 배정 규칙, `working_branch` 선택은 2026-08-17 v3.0에서 삭제했다. 실사용 로그 언급 0~2회, 작업 원장 5건 전부 미사용. 남긴 것은 **잠금판 보존**과 **번호 단조 증가** 두 가지 실질뿐이다.

연작 전체 잠금은 편별 C4와 별개다. 전 편 잠금, 상속·변형의 실제 구현, 전편 순서 통독 또는 낭독을 모두 확인한다.

### C5. 환류

낭독·제출·공연 뒤 다음을 작품카드에 붙인다.

- 예상과 달랐던 자유 회상·오독
- 실제 발화·비언어·공연 시간
- 배우·관객·기술의 병목
- 유지할 선택과 다음 버전 재개 조건

한 작품의 단일 피드백으로 교리를 바꾸지 않는다. 서로 다른 두 작품 이상에서 반복되거나 안전·권리상 중대한 결함일 때 파이프라인 개정 후보로 올린다.

## 6. 중단·보존 조항

사용자는 언제든 중단할 수 있다.

- 구조 가설이 무너지면 B로 되돌리고 재진입 조건을 적는다.
- 동력이 소진되면 `activity: paused`와 재개 조건을 적는다.
- 보관·폐기는 `activity: archived`로 남기며 이력을 삭제하지 않는다.
- 장면 초안·연결본·잠긴 판본은 삭제하지 않는다.
- 구조개작은 부모판과 상속·폐기한 자산을 기록한다.

## 7. 협업 규약

### 7.1 작업 권한

- 문장의 최종 소유권은 사용자에게 있다.
- AI 협업자의 초안은 제안이며, 사용자가 고친 문장이 문체 기준이다.
- 진단은 `원칙 위반`보다 `의도한 것과 지면에 있는 것의 간극`, `선택 렌즈와 긴장하는 지점`을 말한다.
- 대안 문장은 사용자가 요청하거나 승인 봉투에 본문 수정이 포함될 때 제시한다.

### 7.2 승인 봉투

매 단계마다 미세 승인을 요구하지 않는다. 사용자가 회차 범위와 허용 작업을 한 번 승인하면 그 안의 가역적 진단·수정·측정은 묶어서 진행할 수 있다.

새 승인이 필요한 것:

- 형식·작품 동일성 계약 변경
- 부모판에서 새 기준 가지로 승격
- 보호한 강한 자산의 삭제
- C4 잠금
- 외부 제출
- 권리·안전·공모 자격이 불명확할 때의 중단·외부 확인·재설계·목표 변경·제출 철회

### 7.3 다중 에이전트와 가상 낭독

- 독립 렌즈가 실제로 다른 증거를 만들 때만 병렬 에이전트를 쓴다.
- 배우·첫 관객·연출·기술·심사 시뮬레이션은 서로의 결론을 보지 않는 상호 비공개 독립 방으로 나눈다.
- 다수결을 정답으로 삼지 않고 자유 회상, 오독, 회복, 반대 의견을 보존한다.
- AI 다중 낭독은 R0이며 실제 외부 낭독으로 표기하지 않는다.

### 7.4 본문과 전달본

- `script/` 쓰기는 사용자 전담이다.
- AI 협업자는 `drafts/`에서 잠금 후보를 준비하고, 사용자가 `script/`로 이관한다.
- 이관 전후 판본 동일성을 확인한다.

### 7.5 동시 진행

- 사이클 A를 B·C와 별도 세션에서 진행하면 대량 채집이 현재 집필을 방해하지 않는다. 다만 사용자의 즉시 쓰기 충동이 있으면 같은 세션에서 A→B 직행을 허용한다.
- 상태 원장을 동시에 고치지 않는다. 작품별 가지 또는 잠금을 쓴다.
- 권고 기본값은 C 최대 2편(주력 1 + 톤 전환 1), B 1편이다.
- 한도는 운영 권고이지 작품 게이트가 아니다.

## 8. 저장소 어댑터

창작 규약과 특정 운영 환경을 분리한다. 폴더와 대시보드가 달라도 작품 동일성 계약·상태·판본·증거 규칙은 유지한다.

| 폴더 | 역할 |
|---|---|
| `notes/` | 작업 원장·개작 로그·평가·피드백 |
| `maps/` | 원본 창작장치 지도 |
| `draft-candidates/` | 구조 맵·소시험·조건부 어휘/물성표·장면 초안 |
| `drafts/` | 현재 revision·연결본·개작 가지 |
| `plays/<작품>/` | 작품카드 |
| `script/` | 제출·낭독 전달본, 사용자 전담 |
| `contest/` | 공식 요강·AI 규정·제출 기록 |

기존 파일은 일괄 이동·개명하지 않는다. 재활성화할 때 작업 원장이 현재 경로를 인덱싱한다.

### 상태·대시보드

- 계열·병합 지도의 상태 열은 `설계/대기/조립/개작/무대` 다섯 낱말만 쓴다.
- 활동 여부, 가지, 잠긴 버전은 작업 원장에 둔다.
- 대시보드는 원장에서 다시 만들 수 있는 파생물이다.
- 상태 전이와 대시보드 갱신이 일부만 성공하면 그 사실을 기록하고 다음 전이 전 동기화한다.
- 자동화가 있는 환경에서는 원장의 `current_revision`과 체크섬을 확인한 뒤 진행한다.

### 검증

- 파일 이동·개명, 작업 원장·지도·작품카드 갱신, B4·C2·C4 통과 때 위키 검증을 실행한다.
- broken wikilink, frontmatter 오류, 새 placeholder는 변경분 기준 0이어야 한다.
- 플랫폼별 절대경로는 저장소 어댑터에만 두고 파이프라인의 창작 게이트로 삼지 않는다.

## 9. 전환 시험

| 작품 유형 | 기본 경로 | 무겁게 볼 모듈 |
|---|---|---|
| 「저는,」 같은 완성 1인극 | C2 역산 → C3 퇴고 | 1인 발화·침묵, 화면·음향·조명, R2/R3 |
| 「현재 희망 없음」 같은 완성 2인극 | C2 역산 → C3 퇴고 | 잎사귀 앞뒤·게시판 시야·프린터 경로 R3 |
| 「집」 같은 비제도적 이미지/관계극 | B 또는 C 현재 성숙도에서 진입 | 관계·욕망, 이미지·감각·지속 엔진 |
| 연작 | 편별 진입 + F5 공통표 | 편별 독립 완결, 상속, 전편 순서 시험 |
| 장막 | 현재 막/국면의 성숙도에서 진입 | F4 국면 전환, 전편 R2, 대표 병목 R3 |

이 표의 목적은 작품을 유형에 가두는 것이 아니라, 같은 파이프라인이 서로 다른 엔진과 증거를 선택할 수 있는지 확인하는 것이다.
