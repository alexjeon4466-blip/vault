# 공개 커뮤니티 A0→A1 판정 설계 v0.2

> 이 문서는 2026-08-15 채집에서 A0 잔여가 435/537까지 올라간 뒤, `A0 yes`와 실제 쓰기 가능성 사이에 둘 A1 게이트를 설계한 결정 기록이다. v0.2 계약·검증기·합성 테스트·12건 파일럿에 이어 58건 층화 보정 배치까지 구현·검증했다. 기존 A0 435건 전건 적용과 captured 17건 소급 변경은 여전히 승인 범위 밖이다.

## 결정 요약

- **A0는 넓은 잔여 회수 게이트**다.
- **A1은 비발명 구조 증명 게이트**다.
- A1은 A0를 다시 심사하거나 카드·장면·B2를 승인하지 않는다.
- A1은 A0 잔여만으로 5~10줄 구조 메모가 가능한지 증명한다.
- 통과 수 상한과 목표 통과율은 두지 않는다.
- A1 전건 레코드·원문 연결형 메모·exact evidence·review receipt는 Vault·Git 밖에 둔다. pass의 sanitized projection만 `wiki/writing/seeds/notes/`에 사용자 미선택 글감으로 둘 수 있다.
- 최종 카드는 A1 pass의 부분집합이어야 한다.

## 1. A0 — 넓은 잔여 회수

### 책임

A0는 공개 본문에서 다음 가운데 하나라도 원 사건을 버린 뒤 명명 가능한 형태로 남는지 본다.

- 아이러니
- 이상한 질문
- 관계 압력
- 행동
- 물건·소리·공간
- 끊긴 시간·지연·반복
- 말투·리듬·이미지

정치·이념·죽음·돈·질병·법·가족 갈등·폭력·민감성·짧음은 자동 탈락 사유가 아니다.

### 전제

- 공개 본문·게시시각·canonical을 직접 확인한다.
- 서로 다른 정확 근거 span 두 개를 확보한다.
- 두 span은 **독립 출처 두 개**가 아니라 같은 본문 안의 서로 다른 근거일 수 있음을 명시한다.
- `residue: yes/no`와 `source_handling`을 분리한다.
- 한 출처에 독립 잔여가 둘이면 `(source_id, source_version_id, residue_id)` 단위로 나눈다.

### 경계

- A0 yes는 카드 승인·순위·쓰기 승인·A1 pass가 아니다.
- A0의 역할은 회수율을 넓히는 것이므로 통과율 자체를 성과로 보지 않는다.

## 2. A1 — 비발명 구조 증명

### 책임

A1은 A0 yes를 상속하고 다음만 묻는다.

> 원문에 없던 동기·사건·결과를 추가하지 않고도, 이 잔여가 작동하는 공연 규칙을 5~10줄로 기술할 수 있는가?

A1은 `independent_after_redaction`으로 A0의 독립성 판정을 반복하지 않는다. 근거 오류나 residue 오판이 보이면 `resting`으로 낮추지 않고 `a0_recheck`로 반환한다.

### A1이 허가하지 않는 것

- 최종 카드 승인
- 2~5쪽 장면
- 독백·반복 스코어·음향 실험
- B2·형식·길이 결정
- 다음 개발 단계 자동 개방

A1 pass의 직접 권한은 **구조 메모가 존재한다는 기록**뿐이다.

A1 레코드는 `derived_permissions: []`를 명시한다.

## 3. A1 앵커 첫 줄

A1 표시본의 첫 줄은 A0→A1 계보를 보여 주는 앵커다.

```text
1. A0 앵커 — exact / redacted / pointer
```

앵커는 반드시 기존 A0 evidence 두 개 중 하나를 참조한다. A1에서 새롭고 더 자극적인 문장을 사후 선택하지 않는다.

### 앵커 모드

- `exact`: `source_handling=clear`이고 비식별·최소 인용일 때만 허용
- `redacted`: 관계와 행동 연결은 남기되 직접·준식별 단서를 비가역 마스킹
- `pointer`: 인용이 위험하거나 짧은 원문의 실질 대부분을 차지하면 `A0 evidence #1 / 지연·소리 앵커`처럼 위치와 역할만 표시

`blocked / not_run / a0_recheck` stop record는 A1 구조 메모를 만들지 않으므로 `anchor: null`, `proof: null`, `memo_lines: []`를 허용한다. 다만 A0 manifest와 제한 source receipt에는 서로 다른 evidence ID/span 두 개를 감사용으로 유지한다.

### 리뷰 시 처리

- 구조 독립 리뷰에서는 첫 줄과 URL·사이트를 가린다.
- 계보 리뷰에서는 A0 evidence 두 개, 앵커, 원문, 메모를 연다.
- 정확 인용의 연결 기능과 구조 판정의 독립성을 동시에 보존한다.

## 4. 5~10줄 구조 메모

표시본은 다음 의미 필드를 필요한 만큼 합치거나 나눠 5~10줄로 렌더링한다.

1. A0 앵커
2. `protected_core` — 잃지 않을 잔여
3. `source_distance` — 원문에서 버린 범주와 구조로 남긴 것
4. `performance_carrier` — 행동·시간·물건·소리·말투·공간·관객 정보 가운데 압력을 전달하는 수단
5. `tension_topology` — 긴장이나 주의 차이가 조직되는 방식
6. `time_rule`과 `temporal_operation`
7. `terminal_condition`
8. `audience_route` — 독자·관객이 차이를 알아차리는 실행 가능한 경로

첫 줄 외에 원문 대사, 구체 장소·기관·금액, 새 과거사, 해결·교훈·결말을 반입하지 않는다.

줄 수는 렌더링 규칙이다. 검증은 줄바꿈 개수가 아니라 의미 필드와 근거 연결을 본다.

## 5. 미니플롯을 강제하지 않는 증명

### temporal_operation

다음 중 하나 이상을 허용한다.

- 변화
- 누적·마모
- 차이를 가진 반복
- 지연
- 정지·지속
- 회귀
- 재분배
- 분산
- 소멸
- 관객의 지각 재구성

`single_change`와 `irreversible_difference`는 보편 필수가 아니다.

### tension_topology

다음 조직을 동등하게 허용한다.

- 사람–사람
- 몸–환경
- 사람–물건·규칙
- 목소리 내부의 층
- 신호–잡음
- 합창 내부
- 여러 시간대
- 공간–관객 정보
- 위치 없는 감각 충돌

두 인물이나 두 추상 명사쌍을 억지로 만들지 않는다. 무엇이 어느 공연 매체를 통해 주의 차이를 생산하는지 적는다.

### terminal_condition

다음 종결을 동등하게 허용한다.

- 미해결 압력
- 완결·소진
- 절단
- 회귀
- 정지
- 잔류 이미지
- 역할 이전
- 관객에게만 생긴 차이

열린 결말이나 다음 사건을 의무화하지 않는다.

## 6. 발명 없음의 증명

`no_invented_plot=true` 같은 자기신고 불리언만으로 통과시키지 않는다.

앵커를 제외한 각 메모 줄은 다음 중 하나로 분류한다.

- `supported_abstraction`: A0 evidence에서 직접 구조화됨
- `entailed`: evidence가 필연적으로 함축함
- `speculative`: 새 동기·인물·사건·결과·인과를 발명함

각 줄은 `memo_line_id`, `line_type`, `support_evidence_ids`, `transformation_note`, `inference_class`를 가진다.

`speculative` 줄이 하나라도 있으면 pass할 수 없다. 해당 줄을 제거해도 구조가 유지되면 제거 후 다시 심사하고, 제거하면 핵심 운반체·시간 규칙·temporal operation·terminal condition이 무너지면 `structure_state=insufficient`다.

`removed_specifics`에는 실제 제거값을 저장하지 않고 `인물 / 지역 / 기관 / 금액 / 희귀 사건 / 민감 건강·가족 정보` 같은 범주만 기록한다.

## 6.1. 고정 검증 예시

다음은 실제 원문이 아닌 합성 회귀 예시다.

### 민감하지만 A1 pass 가능한 예

```text
A0 앵커(pointer): A0 evidence #1 / 필요한 동안의 침묵과 뒤늦은 신호
보호 핵심: 도움은 필요한 시간에는 침묵하고 끝난 뒤에만 성공을 알린다.
source distance: 가족·기기·장소를 버리고 신호의 시간 순서만 남긴다.
performance carrier: 침묵하는 장치와 뒤늦은 소리.
tension topology: 필요 시간과 알림 시간이 서로 어긋난다.
temporal operation: 지연.
terminal condition: 성공 알림이 도움의 실패를 확정한다.
audience route: 침묵 뒤 단 한 번의 소리로 시간차를 듣는다.
```

pointer 앵커로 민감·식별 맥락을 반입하지 않고, 새 사건 없이 시간 규칙이 서므로 pass할 수 있다.

### 단일 변화가 없어도 pass 가능한 예

```text
A0 앵커(pointer): A0 evidence #2 / 같은 문장의 발음 길이 변화
보호 핵심: 같은 말이 반복될수록 한 음절은 길어지고 한 단어는 사라진다.
source distance: 화자 신원과 사연을 버리고 발화 규칙만 남긴다.
performance carrier: 목소리·호흡·누락되는 단어.
tension topology: 한 목소리 안에서 문장과 호흡이 서로를 침식한다.
temporal operation: 차이를 가진 반복과 소멸.
terminal condition: 문장 대신 들숨만 남는다.
audience route: 반복마다 길이와 누락을 귀로 비교한다.
```

단일 사건이나 두 인물이 없어도 실행 가능한 음성 규칙과 종결 조건이 있으므로 pass할 수 있다.

### A0 yes이지만 A1 resting인 예

```text
A0 residue: 한 물건이 사흘 동안 같은 자리에 남아 있다.
작성자가 추가한 내용: 주인이 돌아오려 한다 / 문이 열리지 않는다 / 물건이 깨진다.
```

원문 잔여는 A0에 보존할 수 있다. 그러나 돌아오는 사람·잠긴 문·파손 사건이 없으면 구조 메모가 서지 않고, 셋은 모두 `speculative`이므로 `structure_state=insufficient / workflow_state=resting`이다.

## 7. 상태를 직교 분리

```text
evidence_state:
  valid / unverifiable / invalid

safety_state:
  clear / blocked

source_handling:
  clear / transform_only / archive_only / prohibited

structure_state:
  proven / insufficient / not_run / a0_recheck

novelty_state:
  distinct / drift_warning / merge_candidate / duplicate / unresolved

workflow_state:
  pass / resting / merge / not_run / blocked / a0_recheck
```

### workflow_state 파생 규칙

- `pass`: evidence valid + safety clear + handling clear/transform_only + structure proven + novelty distinct/drift_warning
- `merge`: structure proven + 실제 merge 대상 + 공유 엔진 + 남는 차이 + merge 이익 명시
- `resting`: structure insufficient 또는 novelty unresolved
- `not_run`: evidence unverifiable/invalid 또는 handling archive_only
- `blocked`: safety blocked 또는 handling prohibited
- `a0_recheck`: A0 evidence 오류 또는 residue 오판 발견

`blocked`는 안전 사유에만 사용한다. `archive_only`와 `not_run`을 blocked로 합치지 않는다.

여러 조건이 동시에 참이면 다음 우선순위로 하나의 workflow_state를 파생한다.

1. safety blocked 또는 handling prohibited → `blocked`
2. handling archive_only → `not_run`
3. A0 evidence 오류·residue 오판 → `a0_recheck`
4. evidence unverifiable/invalid → `not_run`
5. structure insufficient 또는 novelty unresolved → `resting`
6. novelty duplicate/merge_candidate이고 유효한 merge target이 있음 → `merge`
7. 나머지 pass 조건 충족 → `pass`

duplicate/merge_candidate인데 유효한 target이 없으면 `resting`으로 두고 `merge_target_missing`을 기록한다.

## 8. 자기복제 검사는 구조 추출 뒤에 한다

자기복제 사전 탈락은 순환 논리를 만들기 때문에 폐기한다. 메모가 만들어진 뒤 다음 무대 문법을 비교한다.

- 몸
- 공간
- 매체
- 관객 정보
- 반복 비용
- 시간 방향
- 물질 상태
- 종결 작용

역할·행동 순서 일부만 비슷하면 `drift_warning`을 남긴 채 pass할 수 있다. 독립적인 장면 생성 규칙이 없을 때만 `duplicate` 또는 `merge_candidate`로 간다.

merge에는 `merge_target`, `shared_engine`, `retained_difference`, `merge_gain`이 필수이며 자기참조·순환을 허용하지 않는다.

## 9. 두 개의 독립 리뷰

### 구조 독립 리뷰

가리는 항목:

- 첫 줄 앵커
- URL·사이트
- handling
- 기존 카드 여부

보는 항목:

- performance carrier
- tension topology
- time rule과 temporal operation
- terminal condition
- audience route

### 계보·출처 리뷰

여는 항목:

- 원문과 source version
- A0 evidence 두 개
- 앵커 모드와 선택 근거
- 구조 메모와 줄별 support link

판정 항목:

- 추상화가 원문에 지지되는가
- 식별 단서를 재반입하지 않았는가
- 새 인과·동기·사건·결과를 만들지 않았는가

둘 다 통과해야 `structure_state=proven`이다. 불일치는 부모 재심으로 보낸다.

## 10. 보정과 회귀 사례

통과율 목표나 할당량은 두지 않는다. 다음 다양성 사례를 고정 보정 세트로 둔다.

- 전이형
- 반복·누적형
- 정지·무변화형
- 회귀형
- 비인간 행위자형
- 목소리·리듬형
- 관객 지각 재구성형
- 닫힌 종결형
- 원문에 없는 사건을 덧붙인 발명 음성 사례

감시 지표는 판정자별 통과율 자체가 아니라 다음이다.

- 구조/계보 리뷰 불일치율
- 발명 오류율
- 엔진 유형별 편향
- A0 false-positive·false-negative 표본 재심 결과

통과율은 경보 지표일 뿐 목표값으로 맞추지 않는다.

## 11. 저장과 계보

- 판정 단위는 `(source_id, source_version_id, residue_id)`다.
- URL은 stable key가 아니라 version 속성·alias로 취급한다.
- A0 yes residue_id 집합과 A1 record residue_id 집합이 일치해야 한다.
- 출처 영수증과 구조 메모 저장소는 source_id로만 연결해 분리한다.
- A1 전건 레코드와 원문 연결형 메모는 Vault·Git 밖에 둔다.
- 제거한 개인정보의 실제 값은 별도 목록으로 남기지 않는다.
- 배치 정본에는 A0/A1 상태 집계와 최종 카드만 기록한다. A1 pass의 sanitized projection은 URL·사이트·본문·exact evidence 없이 `seed-note / a1-pass-unselected`로 분리할 수 있다.
- 최종 카드는 `(source_version_id, residue_id, a1_record_id, a1_version)`으로 A1 pass에 연결한다.
- source 삭제·handling 변경·안전 재분류가 생기면 카드도 재심한다.

## 12. 비목표

독립 리뷰에서 제안됐지만 이번 A1에는 넣지 않은 항목:

- `smallest_probe` 선택
- 2~5쪽 장면·독백·음향 실험 승인
- 형식 후보와 길이 진단
- 5분 이상 관객 주의 지속 증명
- 개인 로컬 작업실을 전제로 한 기업형 권한·SLA 체계

이 항목들은 A1의 책임을 넘어 다음 단계의 형식·개발 판단을 선취한다.
