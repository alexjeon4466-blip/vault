# A1 전건 원문 열람 정본 운영

## 결정

공개 커뮤니티 글감이 A1 표본에 들어오면 최종 pass 여부와 관계없이 **전건을 사용자용 열람 정본으로 `wiki/writing/seeds/harvests/`에 남긴다.**

- `pass`, `resting`, `a0_recheck`, `blocked`, `not_run`은 가시성 필터가 아니라 같은 문서에서 읽는 판정 라벨이다.
- Source-hidden은 독립 구조 심사자에게만 적용한다. 비공개 Vault의 사용자용 문서에는 적용하지 않는다.
- 사용자는 원문을 읽은 뒤 연극적 잔여와 AI 확장을 직접 비교해야 한다.

## A1 전건 열람 문서에 남길 것

각 항목은 다음 순서를 따른다.

1. 게시물 제목
2. 상태·사이트·게시 시각·원문 URL·handling
3. 접을 수 있는 원문 전체
4. A1까지 온 이유
5. 원문에서 확실히 남는 연극적 요소
6. AI 확장·참고 아이디어
7. pass하지 못했거나 중단한 이유
8. 작가가 다음에 볼 것

운영 코드·hash·source ID·evidence ID·validator 전문은 사용자 본문에 넣지 않는다. 필요한 집계는 짧은 부록으로 내린다.

## 원문 보존과 마스킹

- 로그인 없이 공개된 원글 본문은 비공개 Vault에 보존할 수 있다.
- 원문임을 분명히 하고 사이트·게시 시각·canonical URL을 함께 남긴다.
- 댓글·답변·レス·트랙백 본문은 해당 채집 계약이 열지 않은 한 반입하지 않는다.
- 전화·이메일·계좌·주소·실명과 고유 이력의 결합, 핸들·외부 표적 식별자, 공개키·서명 블록, 자격 증명은 필요한 부분만 `[식별정보 마스킹]` 또는 `[식별정보/키 블록 마스킹]`으로 대체한다.
- 민감 주제·정치·질병·돈·가족 갈등·성별 차별은 자동 마스킹 사유가 아니다. 잔여를 성립시키는 내용 축은 지우지 않는다.
- `blocked`도 문서에서 사라지지 않는다. 마스킹한 원문과 중단 이유를 보여 주되 개발 권한은 열지 않는다.

## Vault 밖에 계속 둘 것

- 원시 HTML과 이미지 cache
- 크롤러 queue·opened 전건·request receipt
- A0 전체 모집단 body와 전건 URL
- 댓글·답변·レス·트랙백 본문
- source hash·exact evidence 전건 ledger·review receipt·validator fixture
- 쿠키·로그인 상태·로컬 API 값·자격 증명

즉 Vault 밖 저장은 **재현·감사·크롤링 작업물의 경계**이고, A1 사용자 열람 결과를 숨기는 경계가 아니다.

## Harvest와 seed-note의 차이

- A1 전건 원문 열람 문서는 배치 단위 `seed-harvest`다. 사용자에게 A1 표본 전체를 보여 주는 정본이다.
- `seed-note`는 A1 pass 뒤에도 사용자가 장기 개별 글감으로 따로 붙잡고 싶을 때만 만든다.
- 전건 열람 문서에 들어왔다고 카드 승인·사용자 선택·장면·인물·대사·형식·길이·B2 권한이 열리지는 않는다.
- 모든 미선택 항목은 `derived_permissions: []`를 유지한다.

## Git·공개 경계

이 Vault는 비공개 작업실이지만 원문을 포함한 A1 전건 문서는 자동으로 commit·push하지 않는다. commit·push는 사용자가 별도로 요청할 때만 수행하며, 공개 전환이 생기면 원문 인용 범위와 식별정보를 다시 검토한다.

## 적용 시작

- 한국 공개 커뮤니티 배치 72: A1 24건
- 일본 공개 커뮤니티 배치 71: A1 12건

기존 source-detached review는 판단 이력만 남기고, 사용자 열람의 기준은 `harvests/` 아래 A1 전건 원문 문서로 전환한다.
