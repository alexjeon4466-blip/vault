# 글감 채집 폴더 운영 및 체크포인트 — 2026-08-15

## 결정

글감 채집의 장기 정본은 `wiki/writing/seeds/` 아래에서 역할별로 관리한다.

- `seeds/harvests/`: 채집 회차 정본
- `seeds/notes/`: A1 pass 뒤 장기 보존하는 sanitized 개별 글감
- `writing/draft-candidates/`: 사용자 명시 선택 뒤에만 들어가는 개발 후보

상태별 폴더를 만들지 않는다. `pass`, `resting`, `selected`는 frontmatter와 외부 심사 package의 상태이며 폴더 이름이 아니다.

## 왜 분리하는가

기존 `wiki/writing/notes/`에는 채집 회차, 개별 창작 노트, 쓰기 탐색, 작업 원장이 함께 쌓여 있었다. 그 결과 다음 경계가 흐려졌다.

1. 배치 전체의 수집·접근·수율 회계와 개별 글감의 장기 구조가 같은 역할처럼 보였다.
2. A1 pass가 카드 승인이나 장면 집필 허가처럼 오해될 수 있었다.
3. 원문·exact evidence·review receipt가 필요한 감사 장부와 비식별화한 장기 위키 노트의 보존 기준이 달랐다.
4. 과거 append-only 로그의 옛 경로가 많아 무리한 일괄 이동은 링크와 계보를 깨뜨릴 위험이 있었다.

따라서 **배치 / 글감 / 개발 후보 / 외부 감사 장부**를 분리한다.

## 저장 경계

| 층 | 정본 | 허용 | 금지·보류 |
|---|---|---|---|
| 전건 감사 | Vault 밖 private archive | 원문, exact evidence, 전건 URL, A1 package, review receipts | Vault·Git 반입 |
| 배치 정본 | `seeds/harvests/` | 범위, cutoff, 접근 경계, 집계, sanitized 카드 | 원시 HTML·JSON, 로컬 임시 경로 |
| 개별 글감 | `seeds/notes/` | A1 pass의 sanitized 구조, opaque lineage ID | URL, 사이트, 작성자, exact evidence, 식별 단서 |
| 개발 후보 | `writing/draft-candidates/` | 사용자 명시 선택 뒤의 설계·집필 | A1 pass만으로 자동 승격 |

Temp는 장기 private archive가 아니다. 외부 package의 영구 보존 위치가 정해지기 전에는 삭제 가능성을 열린 위험으로 기록한다.

## A0·A1·사용자 선택의 권한 경계

```text
A0 yes
  = 보존할 잔여가 있음
  ≠ A1 pass

A1 pass
  = 원문에 없는 인과를 만들지 않은 구조 메모가 성립함
  = seeds/notes/에 sanitized projection을 둘 수 있음
  ≠ 카드 승인 · 사용자 선택 · 장면 · 형식 · 길이 · B2

사용자 명시 선택
  = 지정한 다음 탐색만 개방
```

`seed-note`는 `seed_state: a1-pass-unselected`와 `derived_permissions: []`를 유지한다. 원문 연결형 전건 메모는 외부에 두고, Vault에는 출처를 복원할 수 없게 최소화한 projection만 둔다.

## 구현 체크포인트

### 완료

- `wiki/writing/seeds/harvests/`와 `seeds/notes/`의 역할 계약 확정.
- `seed-harvest`·`seed-note` 타입을 SCHEMA에 추가.
- `wiki/writing/seeds/README.md` 허브 생성.
- 일본 공개 커뮤니티 v2 배치 70 정본 1개를 새 `harvests/` 구조에 적용.
- 배치 70은 최신 provisional 11건을 부모 독립 재독해 `captured 1 / excluded 10 / 사용자 선택 0`으로 확정.
- 외부 A1 58건 package의 현재 상태를 `pass 8 / resting 21 / a0_recheck 19 / blocked 10`으로 재확인.

### 아직 하지 않음

- 기존 `wiki/writing/notes/글감_채집_*.md` **35개** 이동
- 옛 경로 redirect **35개** 생성
- live backlink를 새 정본 경로로 전환
- A1 pass **8개**를 `seeds/notes/`로 생성
- 외부 전건 package를 Temp가 아닌 장기 private archive로 이전
- 사용자 선택·카드 승인·장면·형식·길이·B2
- Git commit/push

### 재확인된 이동 전 위험

- 옛 경로 참조는 현재 **51개 파일 / 189회**다. 이전 계획 당시의 47개/184회보다 늘었다.
- `SCHEMA.md`, `index.md`, 두 로그, 결정 README에는 이번 작업과 무관한 기존 변경이 함께 있다. reset·checkout·전면 덮어쓰기를 금지한다.
- 기존 35개 본문과 frontmatter는 사용자 작업일 수 있으므로, 이동 직전 hash manifest를 새로 만들어야 한다.

## 재개 순서

1. `git status`와 대상 파일 목록을 다시 고정한다.
2. 기존 35개 정본의 filename·본문 hash·frontmatter를 외부 migration manifest에 기록한다.
3. 외부 A1 package의 pass ID 8개와 validator 상태를 다시 확인한다.
4. 옛 경로 참조 수를 다시 계산한다. 숫자가 달라지면 현재값으로 manifest를 갱신하고 추정 이동하지 않는다.
5. 새 정본 35개와 옛 redirect 35개를 한 manifest로 만들고 본문 hash를 검증한다.
6. append-only 과거 로그는 고치지 않고, 현재 live backlink만 새 경로로 바꾼다.
7. pass 8건은 URL·사이트·원문·exact evidence 없이 `seed-note`로 만든다.
8. 표적 privacy·lineage·link·frontmatter 검사와 전역 위키 검사를 분리해 실행한다.

## 다시 열 조건

- 기존 35개 이동은 manifest의 중복·누락·hash mismatch가 0일 때만 실행한다.
- pass 8개 반입은 외부 package가 그대로 검증되고 sanitized projection의 금지 필드가 0일 때만 실행한다.
- 약 100건 A1 확대는 하지 않는다. evidence-lock을 적용한 fresh runnable 24건 보정 뒤에만 다시 결정한다.
- private archive 위치는 사용자가 보존 위치를 정하거나 안전한 Vault 밖 경로가 승인될 때 다시 연다.
