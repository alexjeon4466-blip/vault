# 공개 커뮤니티 글감 채집 풀 운영 규칙

## 결정

공개 커뮤니티 희곡 글감 채집은 다음 네 곳을 `핵심 2 + 보조 2`로 사용한다.

1. **핵심** — 인스티즈 `일상`: https://www.instiz.net/name
2. **핵심** — 클리앙 모두의공원: https://www.clien.net/service/board/park
3. **보조 B** — 82cook 자유게시판 `bn=15`: https://www.82cook.com/entiz/enti.php?bn=15
4. **보조 B** — 루리웹 `고민상담 300147`: https://bbs.ruliweb.com/community/board/300147

모든 레인은 실행 시점 직전 24시간을 우선 창으로 사용하며 미달을 허용한다. 82cook과 루리웹은 **게시글 원문 본문만** 수집·판정하고 댓글·답글·JSON-LD comment를 열람 근거·보강 자료·카드 근거에서 모두 제외한다. 루리웹은 query 없는 정확한 `300147` 목록(1페이지), 그 목록의 `?page=N` 페이지(양의 정수 `page` 하나만, 2026-10-31 개정), `/community/board/300147/read/<id>` 경로만 허용하며 `cate=` 등 다른 query와 일반 보드 `300143`은 요청하지 않는다. 클리앙은 `/service/board/park` 목록(`od`·`po` 정렬·페이지 query 포함)과 `/service/board/park/<id>` 본문만 허용하고, robots가 금지하는 `/service/group/`·`sold`·`hongbo`·`search`는 요청하지 않는다.

오늘의유머·FMKorea·MLBPARK는 과거 기록을 보존하되 현행 풀에서는 비활성화한다. 오늘의유머는 공개 `block_claim` 경로가 반복됐고, FMKorea는 robots가 허용하는 `/best`에서도 stateless 원문 재독이 HTTP 430으로 재현되지 않았으며, MLBPARK는 일반 수집 UA에 전면 금지다. 보배드림은 예비 B로만 보존하고 인벤 오픈이슈갤러리·뽐뿌·더쿠·루리웹 일반 보드 `300143`은 포함하지 않는다.

### 2026-10-31 클리앙 진입 경로 교정 · 보배드림·인벤 재평가

- 클리앙 0건의 원인은 사이트 차단이 아니라 승인 진입점이었다. 현재 robots `User-agent: *`는 `Disallow:/service/group/`로 기존 진입점 `/service/group/community`를 금지하고, `Allow:/service/board/`로 게시판 경로를 허용한다. 그래서 핵심 2번의 진입점을 같은 커뮤니티의 대표 게시판 `/service/board/park`로 교정한다. 소스 계열·상한·본문 기준은 바뀌지 않는다.
- 클리앙 robots는 `anthropic-ai`·`Claude-Web`을 이름으로 금지한다. 실행 주체별 판정(Hermes는 자기 토큰, Claude는 Anthropic 계열 전체)에 따라 클리앙과 인스티즈는 Hermes 레인으로만 수집한다. Claude 실행에서의 미수집은 사이트 수율 0이 아니라 `robots_denied` 정책 중단으로 회계한다.
- 클리앙 모두의공원 품질 표본은 아직 없다. 첫 Hermes 실행의 공개 본문·텍스트 독립·A0 잔여·취급 위험을 기록하고, 기존 `/service/group/community` 시기 결과와 비교한다.
- 보배드림 `freeb`를 2026-10-28~31 72시간 창, 날짜별 균등 표본으로 재평가했다(Claude 단독 판독, 독립 재독 없음). 창 안 11건 가운데 공개 텍스트 본문 9, 텍스트 독립 6/11, A0 유사 잔여 약 4/11, 취급 위험은 대체로 낮았다. 08-29의 텍스트 독립 4/10보다는 높지만 보조 승인 기준(루리웹 100%·80%, 82cook 잔여 8/10)에 못 미쳐 **예비 B를 유지**한다.
- 인벤 오픈이슈갤러리 `2097`은 같은 방식으로 창 안 10건 가운데 텍스트 독립 1/10, A0 유사 잔여 약 1/10이었다. 링크·기사·짤 재게시와 정치 비방 비중이 높아 `C`로 기록하고 풀에 넣지 않는다.
- 루리웹 목록 페이지 탐색을 허용한다(사용자 승인). 종전 "query 없는 목록만" 규칙으로는 1페이지밖에 읽을 수 없어, 느린 보조 레인에서도 24시간·7일 창의 앞쪽 몇 시간만 보였다. 1페이지는 query 없는 경로 그대로 두고, 2페이지부터 `?page=N` 하나만 붙인다. `cate=` 등 분류·검색 query 금지와 `300143` 제외는 그대로다. 각 페이지 URL은 요청 직전 robots로 다시 판정한다.
- 뽐뿌 `freeboard`(목록 HTTP 403)와 아카라이브(Cloudflare 챌린지 403)는 접근 경계로 기록했다. 우회하지 않는다. 표본 원문은 Vault·Git 밖 임시 경로에만 두었다.

### 2026-10-30 검증된 접근 조건 고정 — 에이전트 임의 강화 금지

- 스킬 작성·소스 승인 때 실제로 검증한 접근 조건을 기준선으로 유지한다. 새 실행은 기간과 현재 사이트 증거를 갱신하는 것이지, 접근 정책을 매번 새로 만드는 절차가 아니다. 이 규칙은 한국·일본 공개커뮤니티 채집에 공통 적용한다.
- 실제 사용하는 수집 주체와 해당 robots 그룹·wildcard의 경로 규칙을 적용한다. `ChatGPT-User`, `OAI-SearchBot`, `GPTBot` 등 다른 이름의 봇 제한을 AI 사용·모델 제공자가 같다는 이유만으로 확대 적용하지 않는다. 여러 봇 이름이 모두 허용해야 요청한다는 AND 조건을 금지한다.
  - **명시적 예외(2026-10-31 사용자 결정):** 요청 주체가 Claude(Anthropic 모델의 직접 요청)일 때는 `Claude-User`·`ClaudeBot`·`Claude-Web`·`anthropic-ai`·`Claude-SearchBot`을 다른 회사의 다른 이름이 아니라 같은 주체의 이름으로 본다. 그래서 이 가운데 하나라도 해당 경로를 금지하면 Claude는 그 사이트를 수집하지 않는다. 글감 채집 스킬 개정 세션에서 사용자가 선택지 "Anthropic 계열 전체 차단으로 존중"을 골랐다. 이 예외는 Hermes나 다른 회사 봇 이름으로 확대하지 않는다.
- 에이전트는 '더 보수적으로', '안전하게'라는 이유만으로 중단 조건·진입 경로 제한·더 작은 요청 예산·추가 채택 조건을 임의로 만들지 않는다. 재량적 기준선 변경은 사용자 명시 승인 전 적용하지 않는다.
- 현재 사이트의 실제 변화는 별개다. 적용되는 robots 금지, 로그인벽, HTTP 403·챌린지·429 등 새 제한이 관측되면 해당 요청·사이트를 멈추고 URL·실제 요청 주체·규칙 또는 상태·확인 시각·변경 증거를 보고한다. 과거 접근 성공으로 현재 제한을 무시하지 않으며, 한 사이트의 제한을 다른 사이트나 영구 정책으로 확대하지 않는다.
- 실제 적용되는 금지를 피하려고 UA를 바꾸거나 수집 주체를 허위 표시하지 않는다. 독립적으로 적용되는 명시적 사이트 전체 제한, 로그인·회원 세션·기존 쿠키·요청 한도, 원문/댓글 경계, 승인 소스·날짜·정규주소 기준은 유지한다.
- 이전 배치를 복사할 때 NEW 계약과 요청 코드의 접근 조건을 이 기준선으로 다시 구성한다. 에이전트가 덧붙였던 `extra_conservative_rule`, `provider_policy_conservative_stop`, 이름별 AND 조건을 새 실행에 승계하지 않는다. 과거 계약·수집 코드·실패 영수증은 당시 기록으로 보존하며 소급 수정하지 않는다.
- 실행 전 계약과 실제 요청 조건을 대조한다. **우리 주체 허용 + 다른 이름 봇 금지 → 해당 금지만으로 중단하지 않음**, **실제 적용 wildcard 경로 금지 → 중단**, **요청 주체 변경 없음**을 확인한다. 기준선과 다른 새 수집기는 먼저 바로잡고, 그 불일치를 사이트 접근 실패로 보고하지 않는다.
- '요청 전 정책 중단', '요청 후 기술 차단', '발견 실패', '날짜/정규주소/표본 탈락'을 별도 회계한다. 미요청·미발견을 사이트가 막았다는 뜻이나 검증된 수율 0으로 쓰지 않는다.

### 2026-08-29 핵심 2 + 보조 2 변경 근거

- 최근 한국 배치 6회에서 오늘의유머 공개 본문은 초기 2회만 확보됐고 뒤 4회는 연속 0건이었다. 2026-08-29 재검사에서도 목록과 원글 10건 모두 `block_claim`으로 이동해 공개 본문 `0/10`, 등급 `C`였다.
- 82cook은 최근 6회 중 3회가 0건이었지만 나머지 3회에는 공개 본문 117–124건이 있었다. 같은 날 현재 표본은 공개 본문 `10/10`, 텍스트 독립·A0 유사 잔여 `8/10`, 등급 `B`였으므로 안정적 핵심이 아니라 엄격 필터 보조로 유지한다.
- 루리웹 `300147` clean-room 표본은 공개 본문 `5/5`, 텍스트 독립 100%, A0 유사 잔여 3축 이상 80%였다. 댓글·답글·JSON-LD comment 파싱은 0바이트였고 validator 오류도 0이었다. 다만 중간 이상 handling 위험이 80%이고 게시 속도가 느려 보조 B로만 승인한다.
- 루리웹 일반 `300143`은 텍스트 독립 0%, 이미지·재게시 의존 100%, A0 유사 잔여 0%라 제외한다. 보배드림 `freeb`는 공개 `10/10`이나 텍스트 독립 `4/10`·낮은 위험의 생활 장면이 희소해 예비 B로 남긴다. FMKorea `/best`, MLBPARK, 뽐뿌, 더쿠는 `C`로 유지한다.
- 접근 성공이나 표본 수만으로 승격하지 않았으며, 향후에도 실제 공개 원문·텍스트 독립성·A0 잔여·handling 위험을 직교 비교한다. 보조 레인의 미달을 핵심 레인이나 비승인 사이트로 자동 보충하지 않는다.

### 2026-08-15 승격 근거

- 같은 고정 절단 시각의 공개 본문을 전건 재독했다. 오늘의유머는 범위 내 19건 중 공개 본문 15건, 82cook은 공개 본문 23건이었다.
- 직접 재독과 독립 재독이 합의한 A0 극작 잔여는 오늘의유머 14/15(93.3%), 82cook 19/23(82.6%)였다.
- 종전 `1건·1건`은 실제 극작 잔여율이 아니라 원 사연을 거의 그대로 직접 카드화하기 쉬운 글의 보수적 수율로 정정한다.
- 정치·죽음·돈·질병·법·가족 갈등 같은 민감 소재는 A0 자동 탈락 사유가 아니다. 극작 잔여와 취급 위험을 분리하고, 필요한 경우 인물·지역·기관·금액·고유 문장을 버린 `transform-only`로 남긴다.
- 접근 게이트는 완화하지 않는다. 로그인·회원 세션·기존 브라우저 쿠키·차단 우회를 쓰지 않고, robots 허용 경로의 공개 본문·게시시각·고정 URL만 사용한다.

### 2026-08-15 A0→A1 승인 계약

- A0는 원 사건을 버린 뒤에도 명명 가능한 질문·아이러니·행동·관계·물건·소리·시간·말투·리듬이 하나라도 남는지 보는 넓은 회수 게이트다.
- A1은 A0 yes를 다시 심사하거나 순위를 매기지 않는다. 원문에 없는 동기·사건·결과를 만들지 않고 5~10줄 공연 규칙을 쓸 수 있는지만 증명한다.
- A1의 첫 줄 앵커는 `exact / redacted / pointer` 중 하나지만, 구조 리뷰에서는 앵커·URL·사이트·기존 captured/resting 상태를 가린다. 별도 계보 리뷰는 원문과 A0 근거 두 개를 열어 줄별 지지·식별자 재반입·새 인과 발명을 검사한다.
- 단일 변화·비가역 차이·열린 결말을 보편 필수로 두지 않는다. 변화·누적·차이를 가진 반복·지연·정지·회귀·재분배·분산·소멸·관객 지각 재구성을 동등한 시간 작용으로 인정한다.
- A1 레코드와 메모·리뷰 영수증은 Vault·Git 밖에 둔다. 정본에는 상태 집계와 최종 카드만 남기며, 최종 카드는 A1 pass의 부분집합이어야 한다.
- 이번 승인 범위는 계약·검증기·합성 테스트와 배치 68의 층화 12건 파일럿까지다. A0 435건 전건 소급 판정과 기존 captured 17건 상태 변경은 별도 승인 전 금지한다.
- 상세 상태·스키마·검증 규칙은 [[wiki/writing/decisions/공개커뮤니티_A0-A1_판정설계_2026-08-15|A0→A1 판정 설계 v0.2]]가 권위 기록이다.

### 2026-07-31 변경 근거

- 82cook은 현재 환경에서 로그인 없는 공개 목록을 안정적으로 재현하지 못해 production 풀에서 뺐다. 과거 캐시와 실패 영수증은 역사 기록으로 보존한다.
- 인스티즈 `일상`은 로그인 없는 `/name` 목록과 `/name/<숫자 ID>` 본문, `robots.txt` 허용, 고정 canonical URL, 게시 시각 metadata, 본문 selector를 bounded read-only smoke에서 확인해 대체 소스로 승인했다.
- 목록·본문에 붙는 댓글 수 badge는 제목에서 제거한다. crawler는 어떤 글도 자동 채택하지 않으며 `accepted=0`으로 남긴다.
- 학교·직장·나이·가족·연애·지역 등 식별 단서가 섞인 생활 사연은 별도 윤리 검토 뒤 제외하거나 강하게 변형한다.

## 수량

- 사이트별 최대 5건.
- 사이트별 5건보다 적어도 정상이다.
- 전체 최대 20건.
- 사이트별 5건·전체 20건 상한은 최종 `captured/card`에만 적용한다. A0 yes와 A1 pass에는 수량 목표나 상한을 두지 않는다.
- 공개 원문·윤리·중복 기준을 통과한 글이 20건보다 적으면 실제 수량으로 종료한다.
- 부족분을 뉴스 기사나 다른 커뮤니티로 보충하지 않는다.

## 본문과 댓글

- 본문만으로 사람·행동·관계·시간·물질이 있으면 채집할 수 있다.
- 댓글은 입장권이 아니다.
- 82cook과 루리웹 `고민상담 300147`은 본문 전용 레인이다. 댓글·답글·JSON-LD comment는 수집·저장·판정·인용하지 않는다.
- 댓글은 본문에 없던 물성, 관계 비용, 생활 반례, 반복 행동을 추가할 때만 보강 자료로 쓴다.
- 댓글의 의학·법률·투자·제품 주장과 개인 경험을 사실로 일반화하지 않는다.
- 닉네임·IP·차량번호·지역·가족 신상 등 식별 단서를 보존하지 않는다.

## 유지하는 안전선

- 원문과 댓글은 로그인 없이 공개 열람 가능해야 한다.
- 게시물 제목·게시일·고정 URL을 보존한다.
- 조회·추천·댓글 수는 탐색 신호일 뿐 사실성이나 작품성 근거가 아니다.
- 정치·이념·죽음·돈·질병·법·가족 갈등·폭력·민감성 자체를 A0 탈락 사유로 쓰지 않는다. 먼저 독립 가능한 질문·아이러니·행동·역할 모순·물건·소리·시간·말투가 남는지 본다.
- 글감 가치와 취급 위험을 `clear / transform-only / source-archive / blocked`로 별도 기록한다. `blocked`는 직접 식별자, 미성년자의 고유한 사적 고통, 현재 진행 중인 자해·안전 위험, 변형으로도 분리하기 어려운 고유 사건처럼 기록·개발 자체를 멈춰야 할 때만 쓴다.
- 혐오·조롱·성적 대상화·연예·스포츠 결과·주식·코인·짤 중심 글도 주제명만으로 자동 판정하지 않는다. 공개 본문에서 독립 가능한 극작 잔여가 없거나, 사실 확인 없이 원 사건을 소비해야만 성립할 때 제외한다.
- 범죄·사고·미성년자·사적 고통을 선정적으로 재현하지 않는다.
- 같은 기사·이미지·사연이 여러 커뮤니티에 반복되면 한 건으로 합치거나 제외한다.
- 기사·SNS 단순 복사 게시물은 댓글에 새로운 생활 장면이 없다면 제외한다.
- 원작성 생활 경험·질문·후기와 구체적 현재 행동을 우선한다.
- 사실과 희곡적 확장을 분리한다.
- 1차 풀 전체를 보존한 뒤 글쓰기 우선으로 최대 3–4건만 확장한다. 0건도 가능하다.
- 뉴스는 필요한 경우 사실 교차확인에만 쓰며 커뮤니티 카드 수에 포함하지 않는다.
