# Multi-select book-seed writing probes

Use when a doctrine-change re-read leaves several book-derived candidates and the user explicitly selects more than one for short exploratory writing.

## Why this matters

The normal attraction gate is narrow, but `0–1` is a default, not a prohibition. If the user explicitly chooses several candidates, do not force another ranking round. Develop them in parallel **only as independent probes**, not as an implied cycle or shared world.

## Workflow

1. **Record the multi-selection.** Update the parent re-mining decision from `selection pending` to `selected`; preserve all unselected source fragments as hold, not failure.
2. **Give each candidate a distinct writing bottleneck and formal fuel.** Examples:
   - voice/relation → continuous two-person dialogue;
   - body/misreading → three-person gesture scene;
   - time/rhythm → discontinuous fragments.
   Do not standardize cast size, place, object, ending, or scene count merely for comparison.
3. **Lock adaptation boundaries before drafting.** List source-specific names, representative situations, signature actions, and existing-vault devices that must not recur. For a reopened book corpus, check both direct adaptation and self-copy against earlier derivative notes.
4. **Write 2–5 pages per candidate in one comparison note.** One file may store all probes, but each remains an independent work. Do not open B2, contest length, draft-candidate status, or a shared cycle.
5. **Run a causal-stage review per scene.** Verify:
   - the visible action creates the ambiguity or transfer rather than convenient forgetting;
   - a specific responsibility/cost actually moves;
   - the audience can track object/body/time states;
   - explanatory lines are removed after action proves the point.
6. **Record separate outcomes.** For each probe: `what came alive / physical state audience must know / flattening risk / next curiosity`. The three may receive different next actions.
7. **Reconcile authority.** Update the parent decision, child design decision, source/book card, current branch map, decisions README, index, and log. Historical zero-yield decisions remain historical/superseded rather than being overwritten.
8. **Verify mechanically.** Count source rows and selected/held states; measure each probe separately; scan forbidden source names/devices in scene bodies; validate frontmatter, wikilinks, tables, placeholders, trailing whitespace, repository tests, and `git diff --check`.

## Review handling

Independent reviewers are advisory. Compare every suggestion against the scene's protected promise. Accept only minimal changes that fix a real causal, omission, or audience-legibility issue. If an asynchronous review arrives after a self-review, treat it as a later revision pass rather than delaying delivery indefinitely.

## Common failure modes

- Enforcing the default `0–1` gate after the user explicitly chose several.
- Turning a shared storage note into a shared universe or cycle.
- Giving every seed the same two-person room, procedural engine, or unresolved-object ending.
- Writing three scenes and then advancing all three automatically to B2 or second scenes.
- Keeping stale `selection pending` language in source tables, book cards, maps, or index entries.
