# 산출물 문서 템플릿

배치 하나가 남기는 문서 **두 개**의 골격이다. 문서 계약 자체는 `wiki/writing/seeds/README.md` §문서 계약과 `wiki/writing/decisions/A1_전건_원문열람_정본_운영_2026-08-17.md`가 정본이다. 이 파일은 렌더링 골격만 고정한다.

**경로 표기 규칙.** 산문에서 `wiki/writing/...`, `log.md`, `index.md`로 적은 것은 **vault 루트 기준**이다. 아래 파일명 골격의 `seeds/harvests/...`는 **`wiki/writing/` 기준**이다(= vault 루트 기준 `wiki/writing/seeds/harvests/...`). frontmatter의 `[[wiki/writing/...]]`는 Obsidian wikilink이므로 **항상 vault 루트 형식을 유지한다** — 기존 문서 전체가 이 형식이라 줄이면 링크가 끊긴다.

## 파일명

```text
seeds/harvests/글감_채집_<YYYY-MM-DD>_<풀이름>_A0-A1_<HHMMSS>.md
seeds/harvests/글감_채집_<YYYY-MM-DD>_<풀이름>_A1전건_원문열람_<HHMMSS>.md
```

- `<HHMMSS>`는 절단 시각이고 **두 문서가 같은 값을 공유한다.** 이게 배치 짝을 잇는 키다.
- `<풀이름>` 실사용: `한국공개커뮤니티`, `해외커뮤니티_일본v3`
- `pass/selected/resting` 같은 상태별 하위 폴더는 만들지 않는다. 상태는 frontmatter로 관리한다.

## 문서 1 — A0→A1 배치 정본

### frontmatter

```yaml
---

updated: <YYYY-MM-DD>

sources: []                        # 배치 정본은 비워 둔다. URL은 전건 열람 문서가 가진다
connected_questions:
  - "[[wiki/shared/questions/...]]"  # wikilink 형식이 표준
related_to:
  - "[[wiki/writing/decisions/공개커뮤니티_채집풀_운영규칙_2026-07-18]]"
  - "[[wiki/writing/decisions/공개커뮤니티_A0-A1_판정설계_2026-08-15]]"
  - "[[wiki/writing/decisions/A1_전건_원문열람_정본_운영_2026-08-17]]"
  - "[[wiki/writing/seeds/README]]"
  - "[[wiki/writing/seeds/harvests/글감_채집_<날짜>_<풀>_A1전건_원문열람_<HHMMSS>]]"
community_pool_version: "2026-08-15"
source_scope: community-only
source_snapshot_required: true
derived_permissions: []
_batch_id: <n>
_a1_batch_id: "<kr|jp>-public-community-<YYYYMMDD>-<HHMMSS>-a1"
_a1_schema_version: "public-community-a1/0.2"
_window_kst: "<시작ISO>/<절단ISO>"
---
```

`_`로 시작하는 필드는 내부 메타데이터다(AGENTS.md §8). 해석 본문처럼 읽히지 않게 최소한으로 쓴다.

### 절 골격

```markdown
# 글감 채집 <YYYY-MM-DD> — <풀이름> A0→A1 <HH:MM>

> 3~4문장. 무엇을 어디서 얼마나 열었고, 무엇을 모집단 밖으로 정정했고,
> A1 상한을 어떻게 고정했고, 무엇을 열지 않았는지.

## 1. 고정 창과 접근 경계
## 2. 수집·A0 회계
## 3. A1 fresh production 고정
## 4. Evidence-lock·메모·독립 리뷰
## 5. 최종 live source reconciliation
## 6. 사용자 열람과 권한 경계
## 7. 검증과 저장 경계
```

절별로 반드시 담을 것:

1. **고정 창과 접근 경계** — 시작·절단 ISO 시각(양끝 포함 여부 명시), 사이트별로 무엇을 열었고 무엇이 막혔는지. **robots 판정과 근거를 여기 남긴다.** 부족분을 어느 사이트로도 메우지 않았음을 명시.
2. **수집·A0 회계** — `listed / title-filtered / opened / current-range / non-empty / accepted`를 층별로 분리. **공개 본문 모집단**을 따로 센다(회원 전용 벽은 A0 `no`가 아니라 모집단 밖). A0 `yes/no`와 handling 분포.
3. **A1 fresh production 고정** — 상한(`clear N / transform-only N`), 직전 외부 장부 exact URL 재등장 제외 건수, 사이트 내부 중복 제거. **실패 뒤 백필하지 않았음**을 명시.
4. **Evidence-lock·메모·독립 리뷰** — evidence-lock pass/fail, 메모 작성 건수, masked 구조 리뷰와 source-open 계보 리뷰 각각의 결과, 불일치 수, 제3 정합화 결과.
5. **최종 live source reconciliation** — 재개방에서 확인 실패한 건, 1:1 교체 내역, 최종 workflow_state 집계.
6. **사용자 열람과 권한 경계** — 전건 열람 문서 링크, 사용자 미선택·`derived_permissions: []` 상태, 열리지 않은 권한 목록.
7. **검증과 저장 경계** — 돌린 검증기와 결과, Vault 안/밖 저장 경계, git commit·push 상태.

## 문서 2 — A1 전건 원문 열람 정본

### frontmatter

```yaml
---
type: seed-harvest
status: stable
created: <YYYY-MM-DD>
updated: <YYYY-MM-DD>
visibility: private
title: "배치 <n> — <풀이름> A1 전건 원문 열람"
sources:                            # A1 고정 표본 전건의 canonical URL. 레코드 수와 같아야 한다
  - "https://..."
connected_questions:
  - "[[wiki/shared/questions/...]]"
related_to:
  - "[[wiki/writing/seeds/harvests/글감_채집_<날짜>_<풀>_A0-A1_<HHMMSS>]]"
  - "[[wiki/writing/decisions/A1_전건_원문열람_정본_운영_2026-08-17]]"
  - "[[wiki/writing/seeds/README]]"
derived_permissions: []
source_scope: a1-full-view
source_body_included: true
community_pool_version: "2026-08-15"
_batch_id: <n>
_a1_record_count: <N>
---
```

`sources` 개수 = `_a1_record_count` = 본문 `## A1-NN` 항목 수. **셋이 어긋나면 완료가 아니다.**

### 문서 머리

```markdown
# 배치 <n> — <풀이름> A1 <N>건 전체 보기

> A1 고정 표본 <N>건을 pass 여부와 관계없이 모두 보여 주는 비공개 사용자 정본이다.
> Source-hidden은 심사자에게만 적용한다. 상태는 가시성 필터가 아니라 판정 라벨이며,
> 원문·연극적 잔여·AI 확장·판정 이유를 함께 읽는다.

## 읽는 법

- 원문은 접힌 블록으로 두되 제목·사이트·시각·URL은 바로 보이게 했다.
- 상태 집계: `pass N` / `resting N` / `a0_recheck N` / `blocked N` / `not_run N`.
- 전건 사용자 미선택이며 `derived_permissions: []`이다. A1 pass가 있어도 카드·장면·형식·길이·개발 권한은 자동으로 열리지 않는다.
- 댓글은 포함하지 않았다. 전화·이메일·계좌·주소 등 직접 식별정보가 발견될 때만 해당 부분을 마스킹한다.
- 운영 ID·해시·근거 식별자·검증 전문은 외부 감사 묶음에 남기고 이 문서에는 넣지 않는다.
```

### 항목 골격 — 전건 반복

`A1_전건_원문열람_정본_운영_2026-08-17.md`가 정한 8항목 순서를 그대로 따른다.

```markdown
## A1-<NN>. <게시물 제목>

- 상태: `pass | resting | a0_recheck | blocked | not_run`
- 사이트: `instiz | clien | 82cook | todayhumor | ...`
- 게시시각: `<ISO+09:00>`
- 원문 URL: https://...
- handling: `clear | transform_only | archive_only | prohibited`

<details><summary>원문 전체 보기</summary>

<공개 원글 본문 전체. 원문임을 분명히 한다. 직접 식별자만 [식별정보 마스킹]으로 대체>

</details>

### A1까지 온 이유

### 원문에서 확실히 남는 연극적 요소

### AI 확장·참고 아이디어

### 판정 이유

**<workflow_state>.** <구조 검토 / 원문 계보 검토 / 자기복제·병합 경계를 이 순서로>

### 작가가 다음에 볼 것
```

항목 작성 규칙:

- **`### 판정 이유`는 상태 라벨을 굵게 먼저 쓰고 근거를 이어 쓴다.** 상태만 적고 이유를 비우지 않는다.
- **`### 원문에서 확실히 남는 연극적 요소`에는 실제로 잠근 두 span을 인용한다.** 어느 대목이 근거인지 사용자가 원문과 대조할 수 있어야 한다.
- **`### AI 확장·참고 아이디어`는 확인 사실과 분리한다.** evidence-lock에서 멈췄으면 "공연 규칙을 쓰지 않았다"를 명시하고, 참고 방향을 원문 지지 설계로 취급하지 않는다고 밝힌다.
- `blocked`·`not_run`·`a0_recheck`는 앵커·메모가 없어도 된다. **문서에서 사라지지는 않는다.** 마스킹한 원문과 중단 이유를 보여 주되 개발 권한은 열지 않는다.
- 운영 코드·hash·source ID·evidence ID·validator 전문은 본문에 넣지 않는다. 필요한 집계는 짧은 부록으로 내린다.
- `<details>` 앞뒤와 `##`/`###` 앞에 빈 줄을 둔다. 목록 바로 뒤에 `##`가 붙으면 Obsidian 렌더링이 깨진다.

## 마무리 처리

1. `seeds/README.md` **현재 체크포인트** 절에 이 배치 두 문서를 추가하고 누적 숫자를 갱신한다. 과거 계획 숫자로 되돌리지 않는다.
2. `log.md`에 append-only로 기록한다. 기존 항목은 수정하지 않는다.
3. `index.md` 추가는 새 wiki 문서에 적용된다(AGENTS.md §7).
4. 검증기는 **문서 종류에 맞는 것만** 돌린다. 카드노트 검증기를 배치 정본에 걸지 않는다 — `SKILL.md` §검증 표 참고.
5. commit·push는 명시 요청이 있을 때만. 원문 포함 문서는 자동 commit·push하지 않는다.
