# Japanese public-community v2 pressure and evidence

Use this reference only when the live request or the canonical Vault decision opens Yahoo!知恵袋, はてな匿名ダイアリー, or 発言小町. The current Vault decision remains authoritative; this file records verified operational behavior, not permanent quotas.

## 1. Freeze time and lanes

- Treat `오늘` as the rolling 24 hours ending at one recorded JST cutoff unless the user gives a calendar-day scope.
- Derive the 24–72 hour maturity window from that same cutoff.
- Keep fresh and dialogue-pressure lanes separate. Caps are maxima; shortfall is allowed.
- When a user widens the publication window, explicitly bind every lane (including Komachi popularity/editorial) to that window without silently changing the other sampling constraints. Carry the standing morning/afternoon/night freshness caps into worker contracts; an all-night pool may not consume unused daytime slots. If overflow was already read, retain its collection/A0 history but exclude it from final sampling yield in original discovery order, never by semantic attractiveness.
- Pin `access_policy_version: 2026-10-30-verified-baseline-v1` and the tested, user-approved access conditions before launching collectors. Preflight verifies current site evidence; it does not authorize an agent to add stricter policy. Apply the SKILL.md verified-access-baseline rules to both the contract and executable request predicate.
- Freeze the actual unchanged request identities and one applicable-UA/wildcard longest-match method. A different named provider bot's denial is informational, not a veto for this collector. Do not add all-named-bot AND gates, model-provider blanket bans, or discretionary conservative stops. Changes to the approved baseline require explicit user approval, not merely recording the deviation.
- For a genuinely applicable current robots denial or independently applicable site-wide restriction, retain live rule bytes, actual UA, affected URL, timestamp, and changed evidence. Mark unrequested discovery/original/A0 as `not_run`, not HTTP failure or zero yield; stop only affected lanes. Preserve login, rate-limit, original-only, and approved-source boundaries. Never rotate identity to evade a restriction.
- A custom robots parser must finish a group after directives such as `Crawl-delay`, not only after `Allow`/`Disallow`; otherwise a delay-only agent can inherit the next agent's prohibition. Test this with a separate-group fixture before trusting provider-policy stops.
- When no named or wildcard group matches a request UA, apply no group's robots rules. A max-specificity sentinel of `-1` must not select every unmatched group and manufacture a blanket disallow. Test an unmatched UA against a named-only fixture and actual-UA allow/other-bot deny. An inherited agent-only provider-policy conservative stop must be removed from the NEW run's gate; historical stop receipts remain unchanged.
- Keep reusable collectors and the immediately preceding audit ledger in a durable outside-Vault artifact directory, not a prunable Temp/scratch directory. If the predecessor is missing, disclose the narrower Vault-only exact-URL comparison rather than claiming all historical reappearances were checked.
- A strong original outside the selected rank or time lane is a `sampling_gate_exclusion`, not a card. Do not backfill across lanes unless the canonical contract explicitly says so.
- The current v3 contract changes the **post-open adjudication layer**, not these site-specific discovery lanes. Do not change pressure signals, caps, or response-body boundaries merely because A0/A1 changed.

## 2. Hatena aggregate-only pressure

- Discover original IDs from the anonymous diary archive/search, but verify the public original at `https://anond.hatelabo.jp/<YYYYMMDDhhmmss>`.
- Treat the 14-digit URL timestamp as discovery metadata, not the final publication authority. Read `meta[itemprop="datePublished"]` inside the first original section before stripping its footer; it can differ from the URL timestamp by seconds. Validate the exact metadata timestamp against the frozen lane/window, preserve both values and any delta, and hard-stop a missing date rather than silently substituting the ID. Keep request budget for this final original-only metadata/body check.
- Preserve inline Japanese word continuity when normalizing the original: keyword links can split a word, so joining every text node with a newline corrupts exact evidence. Insert breaks only at block/BR boundaries; remove `.share-button`, `.ad-in-entry-block`, and metadata/author controls before hashing. An original heading containing only `■` is genuinely untitled; record that state rather than generating a title.
- On the public Hatena Bookmark entry HTML, public comment count can be checked without reading comment bodies by comparing both aggregate labels:
  - the `entry-info-comment` count;
  - the `entry-comment-title` count.
- Stream the response and close it as soon as both counts and the total bookmark count are found. Record that comment bodies were not parsed or stored. Reject an ambiguous or disagreeing count rather than guessing.
- Do not use robots-disallowed count/API endpoints such as `/api/entry/info`, `/entry.count`, or `/entry/jsonlite` when the current robots policy forbids them.
- Read trackback pressure only from the original entry footer `記事への反応(N)`. Do not parse, store, or use trackback bodies.
- Rank the bookmark-comment and trackback lanes independently, take each lane's capped top set, then deduplicate exactly as the live contract specifies. Do not let total bookmarks substitute for public comment count.
- For body evidence, read only the first original `div.day > div.body > div.section`; remove heading, footer, share controls, scripts, styles, ads, and metadata before normalizing evidence phrases.
- When that section is parsed from a streamed prefix, decode the bytes to a Unicode string with UTF-8 **before** passing them to BeautifulSoup. `BeautifulSoup(prefix_bytes, from_encoding="utf-8")` is not sufficient: in the verified Windows/Python stack the page's encoding hints could still produce Cyrillic-style mojibake **and could attach a later section's footer to the first original, creating a false trackback count**. Use an explicit equivalent of `prefix_bytes.decode("utf-8", errors="ignore")`; ignoring is limited to an incomplete trailing multibyte fragment after the already-complete original section. Do not let a chunk boundary turn an incomplete trailing share-control tag into body text: strip only the trailing incomplete control fragment and require a stable canonical body hash across repeated final reopens before minting `source_version_id`. If the same URL flickers between a valid original and the explicit response/comment boundary, treat the body classification as ambiguous and remove it without backfill; HTTP 200 or one successful parse is not enough.
- Treat mojibake itself as a boundary warning. A streamed prefix may garble `■ anond:<14 digits> 言及先エントリを開く` so a literal `title.startswith("anond:")` test misses an explicit response fragment. Before A0, flag undecodable/garbled titles or bodies and run one full UTF-8 live reopen; if the recovered title contains the `anond:<14 digits>` response marker or `言及先エントリ`, remove the row without backfill, preserve the receipt, and patch the detector to recognize the marker even when it is not the first decoded characters.
- A cloned Hatena validator must use the current batch number, cutoff, and dynamically derived Bookmark entry robots probe. First-implementation RED-test receipts are not recurring-batch requirements; do not let their absence invalidate a current replay/live-evidence package.

## 3. Yahoo failure semantics

- On a public question original, inspect only the Question JSON-LD prefix before `suggestedAnswer` or `comment`; use `answerCount` but do not deserialize, extract, or store answer bodies.
- Locate the actual `@type: Question` object inside the pre-answer JSON-LD prefix rather than trusting the first `@type`, which may be `BreadcrumbList`. Some current pages put the original question text in `Question.name` with no `text`; verify that field against the original question identity, record the field used, and do not mistake an absent `text` for an empty source. Never search a later author or answer object's `name` as a fallback.
- Treat deep Yahoo list page numbers as unproven discovery coordinates: pages can expose overlapping recent IDs instead of progressively older originals. Compare saved ID sets and listed timestamps; report partial historical coverage rather than inferring days from the requested page number.
- When external search finds older Yahoo URLs after a list-coverage shortfall, treat snippet dates as unverified leads and exclude answer previews from collection/adjudication. A discovered old URL does not supply the date/category comparison population or ranking metrics required by a pressure lane; do not append it to a frozen sample as ad hoc backfill. Record the unresolved historical-discovery gap rather than claiming no older posts exist.
- Keep question ID, canonical URL, publication time, category, answer count, and two verbatim body phrases in the receipt.
- Do not project Yahoo HTML `<title>` directly into the user ledger: it may append an answer preview after the question even when the JSON-LD reader stops before `suggestedAnswer`. Preserve the acquisition title in restricted provenance, but derive the displayed question heading from the original question body and test that the preview never enters user-facing title/annotation text.
- Audit both Yahoo list and detail hosts against the approved access baseline before discovery. A cloned `extra_conservative_rule` or actual-UA/ChatGPT-User/OAI-SearchBot AND gate is stale agent-added policy, not an authorized reason to stop; remove it from the NEW contract and request predicate before execution. Actual-UA allow plus another named bot's deny must not emit a policy-stop package. Retain genuine applicable denials and existing date/cap/canonical boundaries, and validate those independently.
- Repeated HTTP 500/403/network errors are an access failure, not verified zero yield. Do not label an all-error run as successful underfill. Preserve the last valid run separately, report which candidates were actually verified, and stop rather than rotating cookies, logins, browser profiles, or bypasses.
- When cloning a prior Yahoo batch validator, bind it to the **current** batch contract/cutoff rather than its historical default path. An approved `canonical_identity_failure` that was removed without backfill is a counted hard stop, not a global validator failure; unexpected network/HTTP failures must still fail validation and remain separately visible. If the collector stopped at that identity failure, resume only unattempted members of the original frozen sample. Keep `selected = opened + identity exclusions` as disjoint exact-URL sets, require the differing canonical in the original receipt, and never rewrite the frozen selection or backfill the excluded slot. Generalize historical coverage/stop prose from the current receipts instead of cloning old dates.
- If a later conservative filter would exclude candidates from a valid run but a reproduction run fails, describe the valid-run sample and the failed reproduction separately. Never use the failed run's empty output as source evidence.

## 4. Komachi original/reply boundary

- Read the original topic body from the current original-body container (verified in August 2026 as `[dusk="topicsIdMainText"]`) and stop before the reply-list boundary.
- Read the original publication label from `#topicsIdArticleHead .topicsId__articleHeadDateTime` when present. It may be Japanese visible text with no `datetime` attribute. Verify against the original-header container, not a plausible-looking timestamp.

- Separate weekly/category popularity, fresh originals, and editorial recommendations. Monthly rankings remain excluded when the canonical contract says so.
- Editorial polls and posts that merely link another topic may satisfy a ranking lane but still fail the event/next-choice review; do not import the linked third-party body to rescue them.
- A cloned Komachi validator must derive the fresh window from the current batch summary/contract. First-implementation RED-test artifacts such as `judge.py` or `red_test_receipt.json` are not recurring batch requirements and must not make an otherwise current batch fail validation.

## Pitfalls

- Hatena search/archive links can occasionally expose a 14-digit-looking ID whose month/day/hour/minute/second tuple is not a valid timestamp. Treat the digit shape as a lead only: parse it defensively, record the malformed ID as a discovery anomaly, and skip it without aborting or backfilling the fixed sample.
- A Yahoo list row can redirect or canonicalize to another Yahoo property (for example a real-estate knowledge page) even when its list URL looked like a Chiebukuro question. Apply the approved-host and exact-canonical gate after the final body-prefix open, remove failures without backfill, and do not let them reach A0 merely because the question text was readable.
- Killing a probe after a selector bug is not final source failure; discard its partial output and rerun only after fixing the parser.
- A process exit caused by intentional termination must not be summarized as evidence loss if an independent verified rerun exists.
- Aggregate counts show conversation pressure, not agreement or factual correctness.
- A browser or HTTP path failing does not authorize another delivery route, profile, or anti-bot workaround.
