# Portable setup and dependency boundaries

## Resolve one recipient-owned contract

On first use read `templates/collection-contract.md` and `templates/writing-context.md`. These are human/agent operating contracts, not configuration files consumed by the bundled Python scripts. Copy them into the recipient's chosen workspace; obtain missing material scope decisions without inventing approval. Do not request passwords or keys in the document.

Resolve `PROJECT_ROOT`, `PRIVATE_ARTIFACT_ROOT`, optional `VAULT_ROOT`, and exact output path. They are conceptual fields, not automatically expanded environment variables. Resolve paths explicitly in any invoked command. Put raw evidence and evaluation traces outside Vault/Git; plain Markdown is sufficient when no Vault is used. Relative `wiki/writing/...`, `index.md`, `log.md` and dashboard conventions in references are optional examples; never invent those files or their test commands.

The recipient's approved source URLs, board IDs, query rules, window, request identity, caps, comment boundary and output mode govern. Reuse the baseline behavior `2026-10-30-verified-baseline-v1`: actual unchanged-UA/wildcard path evaluation, no borrowed named-bot veto, no identity rotation, real current restrictions honored, no agent-added narrowing. The identifier is a policy-version label, not proof of network access or the recipient's consent. Record first approval separately and do not re-open settled scope without a material change.

For Korean collection the packaged four-site pool is an adoptable reference, not automatic authority. A listed site may be currently denied on its listed path. Stop only the applicable request/site; do not substitute unapproved sources. For Japanese collection, exact discovery URLs, rank metrics, freshness/pressure windows, slot caps, deterministic order and duplicate policy must be supplied by the recipient's contract. Operational hints are included, but the original author's private Japanese run contracts and batch collectors are not.

## Optional skill integrations

- `playwriting-dramaturgy`: downstream form, scene, critique and promotion. Not needed for harvesting; if absent, return a selected seed/handoff and do not invent its doctrine or auto-write.
- `internet-research-routing`: research routing convenience. Use available approved public-web search/extraction tools if absent; do not claim a particular vendor or tool is required.
- `obsidian`: optional Vault editing. Without it, save only the authorized Markdown file; no graph/index/log side effects by default.
- `bookclub-wiki-v2`: optional closed-corpus workflow. Book collection is not silently covered by the public-community contract. Without a provided corpus and permission, do not run it.

None of these optional skill folders is bundled or auto-installed. Missing optional integrations must not veto otherwise authorized seed collection. Existing-work/self-copy review requires recipient-provided context; absence is a disclosed limitation, not permission to pretend it passed.

## Actual Python capabilities

`verify-public-community-note.py`, `verify-public-community-a1.py`, and `verify-community-harvest-structure.py` are runnable structural validators. The first two have regression suites. The generic structure checker has a CLI smoke check in this distribution; do not extend that into a claim of full semantic coverage.

`public-community-spider.py` implements fixed-site constructor checks, list extraction, body extraction and Scrapy settings. Its `start()` has no scheduled requests. It does not implement request accounting, list/post callbacks, raw artifact output, resume orchestration, final URL/canonical comparisons, date-window enforcement or the Japanese collector. `target_date` validation is not rolling-window filtering. Settings and fixtures do not prove live access or original-only streaming. Instiz/Clien parsing can include bounded comments; it is unsuitable as-is for a stricter body-only contract. 82cook/Ruliweb fixtures check that returned comments are empty, not that a full HTTP response never contained comments.

Keep `references/scrapy-local-community-crawler.md` as a clearly labeled unimplemented design contract. Do not silently finish the crawler while merely packaging this skill. Agent-driven collection must use tools that actually implement the approved source/body boundaries and preserve receipts; a complete automated collector is separate implementation work.

## Rights and examples

Do not import the sender's private source archive, historical approvals, full-text ledgers, evaluation traces, browser profile, cookies or API keys. Test fixtures are local synthetic HTML/text; domain/path shapes are retained to test parsers, not to authorize live requests. Historical public source procedure and upstream attribution remain in the references. Public availability, robots allowance, anonymization and this skill's MIT declaration do not license third-party post bodies.

## Completion

For installation, confirm the loaded version and resolve every required contract field. For collection, apply the skill's actual-body, scope, time, count and review gates. A clean package, a passed structural test, and a successful harvest are three different claims.
