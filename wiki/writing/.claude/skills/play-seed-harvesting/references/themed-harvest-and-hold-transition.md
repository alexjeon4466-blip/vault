# Theme-led harvest after a user hold

Use this pattern when the user explicitly puts a prior seed on hold and names a new theme cluster (for example, a season, weather condition, and household device).

## Transition discipline

1. **Close the old branch first.** Mark the prior seed `보류(사용자 결정)`, state that its earlier analysis/test remains historical only, and name the explicit release condition. Update index/log before starting the new harvest.
2. **Do not carry momentum across the hold.** No live test, B2, dialogue, or draft from the held seed unless the user explicitly releases it.
3. **Run a duplicate-topology pass.** Search existing notes by theme words *and* neighboring actions/materials. Record protected exclusions such as prior air-routing, shade reservation, broken umbrellas, wet books, mobile laundry, or drainage cleanup. Mentioning an old title in the duplicate note is fine; re-harvesting its engine is not.

## Turning themes into a harvest question

A fixed theme is a **source boundary**, not a thesis. Convert it into a material-condition question:

> What heat, water, air, noise, residue, timing, or temporary repair moves between bodies, rooms, tools, and weather?

Reject items that merely mention the theme. Keep items in which the theme changes a present task, object state, route, cost, waiting time, or bodily arrangement.

## Recommended 20-card shape

- Mix at least three public source lanes, e.g. domestic reporting, public federated social posts, and public personal blogs.
- Preserve exact public URL/date/title; for titleless social posts, write `제목 없음` plus an exact first sentence.
- In every card, separate `확인 사실` from `희곡적 확장`.
- Use a quick map with number, title, theme axis, action/material, and provisional state.
- For an explicitly requested broad-batch workflow, `20 broad → 3–4 meaningful expansions → 0–1 later promotion` is successful.
- Mark the other cards `보류`; do not fabricate equal depth.
- Before user attraction, do **not** assign A/B scores, `유망★`, B2, final length, or a draft. A compact live-test hypothesis may be attached to the strongest 3–4 only.

## Ethical filter

Exclude crime, minors, worker death/injury, and vulnerability-as-spectacle when their suffering is not necessary to the transferable mechanism. For a public personal post, take only the action/procedure/material relation; do not clone the writer's identity, family, or unique losses.

## Verification recipe

Check deterministically before reporting:

- numbered headings and quick-map rows are exactly 1–20;
- 20 public source URLs and 20 each of fact/fiction sections;
- expansion/hold counts match the note;
- no `_scored` filename before triage;
- no broken wikilinks, placeholders, or trailing spaces;
- each URL responds publicly at verification time;
- index and log point to the new note;
- dashboard tests and `git diff --check` pass;
- report explicitly that commit/push was not done unless requested.
