# 채집 계약 — 복사해서 수신자가 작성

이 양식은 실행 승인이나 Python 설정 파일이 아닙니다. 승인된 기존 계약이 있으면 그것을 사용합니다. 빈칸·미결정 값을 에이전트가 과거 사례로 채우지 않습니다.

## 승인·출력 범위

- 계약 ID/버전:
- 요청자 승인 시각과 승인한 범위:
- 실행 단계: A0 / 별도 승인된 A1 / 조사만
- 출력 방식: 대화만 / 지정 Markdown / 승인된 Vault 경로
- 외부 게시·재배포: 별도 승인 전 없음
- Git 인증 변경·commit·push: 별도 승인 전 없음
- PROJECT_ROOT:
- PRIVATE_ARTIFACT_ROOT (Vault/Git 밖):
- VAULT_ROOT (미사용 가능):
- 정확한 산출물 파일/폴더:
- 원문 보존기간/접근자/삭제 승인 절차:

## 시간·표본

- cutoff (시간대 포함):
- 시작 시각/종료 시각:
- `오늘` 기본 해석: cutoff 직전 24시간. 명시적 달력 날짜는 해당 지시를 적용.
- 전수/제한 표본의 구분:
- 목록/원글 요청 예산, 페이지/시간 상한, 선택 순서:
- 사이트별 최대/전체 최대:
- 미달 허용과 대체 금지 조건:
- 과거 중복 비교에 사용할 승인된 기록 (없으면 없음과 한계 명시):

|---|---|---|---|---|---|
| 작성 | 작성 | 작성 | 작성 | 작성 | 작성 |

한국 참고 풀: Instiz 일상, Clien community, 82cook `bn=15`, Ruliweb `300147` (`references/public-community-first-harvest.md`). 이는 채택 가능한 예이지 현재 접근 성공이나 자동 승인 목록이 아닙니다. 한국 카드 검증기는 이 풀 버전의 제약을 검사합니다. 풀을 바꾸면 검증기 지원도 먼저 확인하세요.

일본 사용 시: Yahoo/はてな/発言小町 각각의 발견 URL, fresh/pressure 레인, 비교 모집단, 집계 지표, 순위·동률 순서, 시간대별 슬롯, 제외·미달 처리, 중복 제거 순서까지 적습니다. 원본 질문/주제만 열고 답변·댓글 본문을 읽지 않는 경계를 유지합니다. 숫자는 스킬의 과거 예에서 임의 복사하지 않습니다.

## 접근 기준

- access_policy_version: `2026-10-30-verified-baseline-v1`
- 실제 요청 도구와 고정된 UA/식별:
- 최초 검증·승인한 접근 조건 및 증거 위치:
- 적용 UA/와일드카드·경로별 robots 근거, 독립적으로 적용되는 명시적 사이트 규칙:
- 요청 간격/동시성/재시도·429 처리:
- 인증·가입·기존 사용자 쿠키·CAPTCHA·프록시/신원 회전 없음.
- 다른 봇의 금지를 가져와 전체 허용 AND 조건을 만들지 않음.
- 승인된 조건을 임의 강화하거나 목록/예산/선정 경계를 몰래 줄이지 않음.
- 새로 적용되는 제한은 정확한 URL/UA/규칙·응답/시각을 기록하고 영향받은 요청만 중단.
- 정책 미요청·HTTP 실패·목록 발견 실패·기간 제외·본문 추출 실패·예산 중단을 분리.

## A0·A1·사용자 열람

- A0: 원문 근거와 연극적 잔여를 기록, 민감성과 취급 위험은 별도 축으로 분류.
- A1 승인 범위/실제 표본 수/층화 방식 (미승인 시 실행하지 않음):
- 두 원문 증거 고정 → 메모 → 독립 구조/계보 심사 → 최종 상태.
- A1 전건 표시. pass 외 상태도 원문/출처·판정 이유·참고할 잔여를 표시.
- 사용자 문서의 원문 표시 방식: 허용된 전문 / 제한 발췌+링크 / 기타 승인 방식:
- 전문 재현이 불가능하면 전건 상태는 보존하고 표시 제한을 알림. 전건 섹션 수가 전문 재현을 증명하지 않음.
- 외부 배포물에는 원문·식별정보를 자동 전재하지 않음.

## 완료 기준

- 각 단계와 사이트의 실제 시도/열림/기간 내/본문/잔여/판정 수 및 정확한 URL 집합.
- 읽지 않은 페이지나 미실행 단계를 실패 응답 또는 0수율 성공으로 쓰지 않음.
- 요청한 범위만 완료; A1·집필·승격·추가 소스·공개 서비스로 자동 확장하지 않음.
